# 04 数据模型与坐标系统

> 这一层是最容易「看起来能跑、细节全错」的部分。本文把**单位、变换顺序、层次摆放、
> 两种格式的差异、精度边界**定死，作为 IO 与场景层的共同契约。

---

## 1. 三层坐标空间

| 空间 | 类型 | 含义 | 谁使用 |
|---|---|---|---|
| **DBU** | `int32`（运算用 `int64`） | 文件中的整数坐标单位（database unit） | core / io / scene 的几何存储 |
| **µm** | `double` | 物理尺寸，用户可读 | 相机、渲染、测量、状态栏 |
| **px** | `double`（含 DPR） | 屏幕上像素 | 渲染、拾取容差、UI |

换算关系（全部收敛到 `core::Units` 与 `render::Camera2D` 两处，别处不得自行乘除）：

```
micronsPerDbu = metersPerDbu * 1e6
worldMicron   = dbu * micronsPerDbu
dbu           = llround(worldMicron / micronsPerDbu)
pxPerMicron   = viewportHeightPx * devicePixelRatio / visibleHeightMicron
```

**规则**

1. 几何**只存 DBU 整数**；渲染前才转 µm，且转换点唯一（`Camera2D::toScreen` / 顶点生成）。
2. 界面显示同时给 µm 与 DBU（状态栏、属性面板），避免用户换算。
3. 所有「相不相交 / 在不在框内 / 点到多边形距离」在整数域完成，容差参数单独作为浮点
   像素阈值传入。

## 2. 单位解析

### GDS

`UNITS` 记录含两个 8 字节实数：

- `dbuPerUserUnit`：1 个用户单位 = 多少 DBU；
- `metersPerDbu`：1 DBU 的物理长度（米）。

典型值 `(0.001, 1e-9)` → 用户单位 1 µm、DBU = 1 nm、`micronsPerDbu = 0.001`。

**注意**：GDS 实数不是 IEEE754，而是「符号 1 位 + 指数 7 位（基 16，偏移 64）+ 尾数 56 位」，
需要专门解码（`RealDecoder`），并写单测覆盖：0、1、-1、0.001、1e-9、极大/极小、非规格化值。

### OASIS

OASIS 使用 IEEE754 double，且单位由 START 记录后的 `UNIT` 记录给出
（`dbu per micron` 形式，需按 P39 定义换算成 `micronsPerDbu`）。
缺失时按 1 nm 处理并记 warning。

### 统一模型

```
struct Units {
    double dbuPerUserUnit = 1000.0;
    double metersPerDbu    = 1e-9;
    bool   valid          = false;   // 文件是否显式给出
    double micronsPerDbu() const { return metersPerDbu * 1e6; }
};
```

## 3. 变换（摆放）数学

### 3.1 表示

```
struct Transform {          // 2x3 仿射：p' = M * p + t
    double a = 1, b = 0;    // [a b]
    double c = 0, d = 1;    // [c d]
    double tx = 0, ty = 0;  // 平移（DBU）
    // 原始参数（保留用于属性面板显示、写回文件）
    bool   mirrored = false;
    double mag      = 1.0;
    double angleDeg = 0.0;
    bool   isIdentity() const;
};
```

**乘法约定：行向量** `p' = p · M`，因此 `M = M_parent * M_local`
（等价于列向量的 `M_world = M_local * M_parent`；文档与代码统一一种，注释里写清楚）。

### 3.2 GDS 的变换顺序（易错点）

`SREF`/`AREF` 的 `STRANS` 位 15 表示**关于 x 轴镜像**，随后依次：

```
1) mirror about X axis     (y -> -y)        [仅当 STRANS bit15 置位]
2) rotate by ANGLE         （逆时针，单位度，可为任意实数）
3) scale by MAG            （默认 1.0）
4) translate by XY         （单位 DBU）
```

即 `M = T(xy) · S(mag) · R(angle) · MirrorX`（列向量写法）。
**不要**把镜像和旋转的顺序写反：90° 旋转 + 镜像时结果差异明显。
实现后必须用 KLayout 对照 4 类用例：无变换、纯旋转 30°、镜像+旋转 90°、镜像+缩放 0.5。

### 3.3 OASIS 的变换

`PLACEMENT` 需要依次处理：flip（bit0 = 关于 x 轴反射，bit1 = 关于 y 轴反射）、
`angle`（度，实数，允许非 90° 的倍数）、`mag`、平移。
**OASIS 允许角度与放大倍率是任意实数**，因此矩阵必须用 double 保存，不能用「90° 枚举 + bool」。
同样需要 KLayout 对照验证。

### 3.4 合成与逆变换

```
Transform compose(const Transform& parent, const Transform& local);
Point  apply(const Transform& t, Point p);              // 用 double 算完再 llround
Box    apply(const Transform& t, const Box& b);         // 四角变换后取包围盒
Transform inverse(const Transform& t);                  // 用于拾取（屏幕->cell 局部坐标）
```

- `compose` 在 `double` 域做；**只有最后一步**写回 `Point`/`Box` 时才取整，
  避免逐级取整累积误差。
- 变换栈深度上限 64；每层合成后检查 `mag` 是否退化为 0（病态数据）→ 记 warning 并跳过。

### 3.5 包围盒传播

- `Cell::bbox` = 本 cell 所有图元 bbox ∪ 所有子引用的 `apply(transform, child.bbox)`。
- 用拓扑排序（引用是 DAG）自底向上算一次，O(N)；有环时对环内 cell 用保守并集并标红。
- 顶层 bbox 用于 `zoomFit`、网格步长选择、空间索引范围。

## 4. 图元几何定义（与渲染的对应关系）

| 图元 | 存储 | 渲染 | 命中测试 |
|---|---|---|---|
| `Boundary`（多边形） | 点序列，隐式闭合 | 三角化填充 + 描边（LOD 低时画 bbox） | 点在多边形内（奇偶规则）/ 边距 |
| `Path` | 中心线 + 宽度 + 端点类型 | 按宽度展开为矩形/圆头多边形；极细时画 1 px 线 | 点到线段距离 ≤ w/2 + tol |
| `Box`（GDS BOX，OASIS RECTANGLE） | 5 点或 rect | 同 Boundary（快速路径） | 同矩形判定 |
| `Text` | 锚点 + 字符串 + 字高 + 呈现位 | 屏幕空间 QPainter 文本 | 文本包围盒 |
| `Sref/Aref` | 子 cell + 变换 (+ 阵列) | 递归（见 05） | 递归 + 逐层反变换 |
| `Node` | 点数与坐标 | 不渲染（可调试显示） | 不参与 |
| `XElement` | 原始字节 | 不渲染（占位） | 不参与 |

**Path 端点类型**（GDS `PATHTYPE`）：0 = 平头（flush）、1 = 圆头、2 = 方头（半宽延伸）、
4 = 自定义延伸（`BGNEXTN`/`ENDEXTN`）。渲染时统一转换为多边形，避免路径线宽在不同后端不一致。

**多边形合法性**：允许自交、允许非凸、允许顺时针/逆时针；不做修正（查看器不做 DRC），
但三角化要能容错（退化三角形丢弃）。

## 5. GDSII 格式要点

### 5.1 记录结构

```
[2 字节总长度(含这 2 字节)] [1 字节记录类型] [1 字节数据类型] [数据...]
```

- 全部大端（big-endian）。
- 数据类型：`0` 无数据、`1` 位串、`2` int16、`3` int32、`5` real64、`6` ASCII。
- 字符串：长度由记录长度决定，末尾多余字节可能是 NUL，需要去除。
- **文件没有魔数**：识别靠「后缀 + 首记录必须是 `HEADER(0x0002)`」这一约束。

### 5.2 主要记录（实现清单，编号为记录类型）

| 记录 | 值 | 数据 | 说明 |
|---|---|---|---|
| `HEADER` | 0x00 | int16 | 版本号（通常 600） |
| `BGNLIB` | 0x01 | 12×int16 | 时间戳 |
| `LIBNAME` | 0x02 | ASCII | 库名 |
| `UNITS` | 0x03 | 2×real64 | 见第 2 节 |
| `ENDLIB` | 0x04 | — | |
| `BGNSTR` | 0x05 | 12×int16 | 一个结构开始 |
| `STRNAME` | 0x06 | ASCII | cell 名（≤32 字符） |
| `ENDSTR` | 0x07 | — | |
| `BOUNDARY` | 0x08 | — | 多边形开始 |
| `PATH` | 0x09 | — | 路径开始 |
| `SREF` | 0x0A | — | 单实例引用 |
| `AREF` | 0x0B | — | 阵列引用 |
| `TEXT` | 0x0C | — | 文本 |
| `NODE` | 0x15 | — | 电气节点（不渲染） |
| `BOX` | 0x2D | — | 矩形 |
| `LAYER` | 0x0D | int16 | |
| `DATATYPE` | 0x0E | int16 | |
| `BOXTYPE`/`TEXTTYPE` | 0x2E/0x16 | int16 | 与 datatype 对应 |
| `WIDTH` | 0x0F | int32 | 路径宽度（负数表示绝对宽度） |
| `XY` | 0x10 | N×int32 | 坐标点列（N 为偶数） |
| `ENDEL` | 0x11 | — | 图元结束 |
| `SNAME` | 0x12 | ASCII | 引用的 cell 名 |
| `COLROW` | 0x13 | 2×int16 | AREF 列数、行数 |
| `PATHTYPE` | 0x21 | int16 | 0/1/2/4 |
| `STRANS` | 0x1A | 位串 | 镜像/绝对放大/绝对角度 |
| `MAG` | 0x1B | real64 | |
| `ANGLE` | 0x1C | real64 | |
| `PRESENTATION` | 0x17 | 位串 | 文本对齐/字体 |
| `STRING` | 0x19 | ASCII | 文本内容 |
| `ELFLAGS` | 0x26 | 位串 | 模板/外部数据 |
| `PLEX` | 0x2F | int32 | 分组 |
| `PROPATTR`/`PROPVALUE` | 0x2B/0x2C | int16/ASCII | 属性 |
| `BGNEXTN`/`ENDEXTN` | 0x30/0x31 | int32 | PATHTYPE=4 的延伸 |

### 5.3 解析状态机

```
文件级: HEADER -> BGNLIB -> LIBNAME -> UNITS -> (cells)* -> ENDLIB
cell 级: BGNSTR -> STRNAME -> (element)* -> ENDSTR
element: BOUNDARY|PATH|SREF|AREF|TEXT|NODE|BOX
         -> 属性记录(可多次、顺序不定) -> ENDEL
```

实现要点：

- 用**状态枚举 + switch** 而不是递归下降，便于在任意位置取消/跳过未知记录。
- 每个 element 用「临时累加器」收集属性，遇 `ENDEL` 才提交到 `Cell::shapes` / `Cell::instances`；
  这样单个畸形图元可以被丢弃而不破坏已解析数据。
- `XY` 点数上限 8191（受 16 位记录长度限制）；超过不是"拆分"而是数据损坏，按损坏处理。
- 未知记录：按长度跳过；长度非法则终止。

### 5.4 AREF 摆放语义（重点）

`AREF` 的 `XY` 含 **3 个点**：`P0`（原点）、`P1`、`P2`；`COLROW` 为 `(cols, rows)`。

```
列间距向量 = (P1 - P0) / cols
行间距向量 = (P2 - P0) / rows
第 (i, j) 个实例原点 = P0 + i * 列间距向量 + j * 行间距向量     （i∈[0,cols), j∈[0,rows)）
```

**验证方法**：用 gdstk 生成 `cols=3, rows=2` 的 AREF，已知间距，读回来断言每个实例原点；
再用 KLayout 截图比对。不同工具对「P1 表示最后一列中心还是阵列外框」存在历史差异，
必须以「与主流工具一致」为准，并把结论写进测试用例注释。

**性能**：AREF 不展开成 N 个 `Sref` 存进模型，而是保留 `cols/rows/间距` 或 `Repetition`，
由场景层按需生成实例位置（避免 1e5 实例 × 每条 32 B 的浪费）。

## 6. OASIS 格式要点

> OASIS 复杂度显著高于 GDS，建议**独立里程碑**，并按「能读通 → 能正确渲染 → 性能」三步走。

### 6.1 结构特征

| 特征 | 说明 | 影响 |
|---|---|---|
| 变长整数 | 无符号整数：7 位一组、低字节在前、末字节最高位置 1；有符号整数：符号放在最低位 | 所有数值都走同一个解码器 |
| 字符串 | 长度前缀 + 字节，可能含 NUL 填充 | 需要去掉尾部 NUL |
| 实数 | IEEE754 double | 比 GDS 简单 |
| modal 变量 | 多数属性在 cell/图元范围内「沿用上一次的值」 | **必须在 CELL 边界与图元边界正确重置**，最易出错 |
| delta 坐标 | 点列默认相对上一个点（`XYRELATIVE`/`XYABSOLUTE` 控制） | 解析后统一转绝对坐标再存入模型 |
| 表格 | cell 名（隐式表 0）、文本字符串、属性名/值、层名、XName 等 | 需要 `TableStore`，且编号作用域随文件 |
| CBLOCK | 压缩块（类型 0 = deflate），块内是普通记录流 | 用 zlib 流式解压，块内仍需完整解析，偏移量指向文件而非解压流 |
| REPETITION | 1D/2D/3D，固定/可变步距，正交/对角 | 抽象成 `Repetition` 生成器，不要为每种类型写渲染分支 |
| 属性 | 可挂 cell / 图元 / 摆放 / 库，值为字符串或实数 | 存 `Property{name, value}`，属性面板可显示 |
| offset table | 文件尾部有 cell 名 → 偏移 的索引 | 支持「按需加载单个 cell」（D8） |
| XElement/XName | 厂商扩展，二进制块 | 保留原始字节，不渲染 |

### 6.2 记录（按处理阶段）

1. **头部**：`START`（版本）、`END`。
2. **全局**：`UNIT`、`CELLNAME`（隐式表）、`TEXTSTRING`、`PROPNAME`、`PROPSTRING`、
   `LAYERNAME`、`XNAME`、`FILE` 等表记录。
3. **cell 内**：`CELL`（名字引用/内联）、
   `PLACEMENT`/`PLACEMENT_TRANSFORM`、`TEXT`、`RECTANGLE`、`POLYGON`、`PATH`、
   `TRAPEZOID`/`CTRAPEZOID`、`CIRCLE`、`PROPERTY`、`XYABSOLUTE`/`XYRELATIVE`、
   `REPETITION` 附着于上一条图元/摆放。
4. **压缩**：`CBLOCK`。
5. **尾部**：offset table（`OFFSET` 相关记录），用于懒加载。

> 具体类型码与字段顺序以 **SEMI P39** 官方文本为准；实现时把「每个记录 → 单测用例」
> 一一对应，宁可按规范写慢一点，也不要"看着像"就跳过。

### 6.3 三条高风险规则（写进代码注释）

1. **modal 状态作用域**：进入 `CELL`（含 CBLOCK 内）时重置几何相关的 modal 值，
   但表格/全局设置不重置；`END` 前需 flush。
2. **delta 累积**：所有点列先按 delta 还原为绝对坐标（在 cell 局部坐标系内），
   **再**应用摆放变换；顺序错了会出现「整体偏移」而不是明显报错。
3. **REPETITION 与图元/摆放的绑定**：重复是「上一条元素」的属性；遇到新的图元记录时
   必须清空上一个 repetition 状态，否则会静默出错（渲染出多余图元）。

## 7. 两种格式到统一模型的映射

| 统一模型 | GDSII 来源 | OASIS 来源 | 备注 |
|---|---|---|---|
| `Layout.name` | `LIBNAME` | `START` 内的名字 | |
| `Units` | `UNITS`（base-16 real） | `UNIT`（double） | 统一成 `micronsPerDbu` |
| `Cell.name` | `STRNAME` | 表 0 的 cellname / `CELL` | OASIS 名可长、可含特殊字符 |
| `LayerKey` | `(LAYER, DATATYPE)` | `(layer, datatype)` 或 `LAYERNAME` | OASIS 可用命名层，需保留 nameId |
| `Shape`（Boundary） | `BOUNDARY` + `XY` | `POLYGON` / `RECTANGLE` / `TRAPEZOID` | 统一成多边形（矩形保留快速路径标志） |
| `Shape`（Path） | `PATH` + `WIDTH` + `PATHTYPE` | `PATH`（含半宽/扩展） | 统一成「中心线 + 半宽 + 端点类型」 |
| `Shape`（Text） | `TEXT` + `STRING` + `PRESENTATION` | `TEXT`（含 texttype、层） | OASIS 文本可带 arbitrary 字符串 |
| `Instance`（Sref） | `SREF` + `SNAME` + `STRANS/MAG/ANGLE` | `PLACEMENT` | 变换统一为 `Transform` |
| `Instance`（Aref） | `AREF` + `COLROW` + 3 点 | `PLACEMENT` + `REPETITION` | 统一为 `Repetition` 生成器 |
| `Property` | `PROPATTR`/`PROPVALUE` | `PROPERTY` | 值是字符串或实数，统一成 variant |
| `Shape`（Node/XElement） | `NODE` | `XELEMENT`/`XNAME` | 保留原始字节、不渲染、可回写 |

**语义差异要显式记录**（写进 `docs/known-differences.md`，随代码维护）：

1. GDS 的层是纯数字；OASIS 可能有名字和层号两套标识 → UI 上优先显示名字。
2. OASIS 允许任意角度/放大；GDS 也允许，但历史工具多按 90° 处理 → 渲染必须支持任意角度。
3. OASIS 有 `TEXT` 与 `TEXTSTRING` 表，字符串重复率高 → 建模时字符串驻留（interning）以省内存。
4. OASIS 支持属性挂载到任意层级，GDS 只有 element/cell 上的 `PROPATTR`。
5. OASIS 的 cell 可以「内联」或「引用名字」；GDS 只有名字引用。

## 8. 内存布局与精度边界

### 8.1 目标内存开销

| 数据 | 目标 | 说明 |
|---|---|---|
| `Point` | 8 B | `int32 x, y` |
| `Shape`（Boundary，≤6 点） | 32–64 B | 头部 16 B + 内联点数组；`SlotMap` 另加 8 B 句柄/槽位开销 |
| `Shape`（Path/Text） | 48–72 B | 宽度/端点/字符串 id |
| `Instance`（Sref 等价） | 48 B | cellId(4) + layer(4) + Transform（见下） |
| `Instance`（Aref 等价） | 64 B | 变换 + 行列 + 步距 |
| `CellGeometry` 顶点 | 8–16 B/顶点 | 渲染用 `float` 或 `int16` 量化，见 05 |

> 变换用 6 个 double（48 B）会让每个实例都很重。优化方向：绝大多数变换是
> 「90° 倍数 + 镜像 + 整数平移」，可用**紧凑编码**（16 B）：`{int32 tx, ty; uint8 rot90; uint8 flags; int16 pad}`，
> 只有非正交变换才落到"扩展表"。这是 V1 的性能优化项，MVP 先用 `Transform`（含 double 矩阵）。

### 8.2 精度与溢出

| 风险 | 处理 |
|---|---|
| int32 坐标 **+ 多层平移/放大** 溢出 | 中间一律 `int64`；写回模型前检查范围并 clamp + warning |
| 8 字节 GDS real 解码误差 | 用 `long double` 中间量；单测要求相对误差 < 1e-12 |
| 浮点顶点在大坐标下抖动 | 顶点相对「瓦片原点」存 `float`，模型矩阵用 `double` 在 CPU 计算（见 05） |
| 极小缩放（缩到全图）导致线宽 < 1 px | 线宽最小 1 px；多边形面积 < 2 px² 时画包围盒 |
| 极大 `mag`（如 1e6）导致包围盒爆炸 | 场景构建时对 `mag` 做上限检查并 warning，仍渲染但不参与索引 |
| 层数/数据类型超 16 位（OASIS 允许更大） | 模型用 `uint32` 存 layer/datatype，UI 显示原值 |

### 8.3 字符串与表

- 所有 cell 名、文本字符串、属性名/值走 `StringPool`（`unordered_map<string_view, uint32_t>` + 连续
  字符块），重复字符串只存一次。工业版图里 cell 名/文本重复率极高，这一项能省 20–40% 内存。
- 表编号 → 字符串的映射保留在 `Layout` 层，`Cell`/`Element` 只存 id。

## 9. 验证策略（数据 + 断言）

| 测试 | 数据来源 | 断言 |
|---|---|---|
| real64 解码 | 手工构造 + 真实文件头 | 已知值精确匹配（相对误差 1e-12） |
| 单位换算 | `(0.001, 1e-9)`、`(1e-4, 1e-8)` 等 | `micronsPerDbu` 正确、往返转换无漂移 |
| SREF 变换 | 4 类用例（纯平移/旋转 30°/镜像+旋转/缩放） | 关键点坐标与 KLayout 一致 |
| AREF 布局 | gdstk 生成 3×2、含旋转、含镜像 | 每个实例原点逐一断言 |
| OASIS varint | 0、1、127、128、16383、16384、2^32-1 | 编解码往返一致 |
| OASIS modal/delta | 手工构造的最小文件（含 CBLOCK） | 解析后坐标与预期一致 |
| 坏文件容错 | 截断文件、长度非法、引用缺失 cell | 不崩溃、返回正确 `ErrorCode`、已解析部分可用 |
| 往返 | 读入 → 写出 → 再读入（GDS） | 图元数、层、坐标一致（顺序可比对） |

**样例数据管理**：`tests/data/` 下只放**小体积**且可程序化再生的文件；大文件用脚本
（gdstk/klayout）生成到 `build/testdata/`，不入库。每个样例配一个 `.md` 说明其覆盖点。

## 10. 可变模型的坐标语义（编辑相关）

查看时只需要"读得对"，编辑时必须定义"改得合法"。以下规则同时约束内核与 UI。

### 10.1 坐标的唯一真相是 DBU 整数

- 用户输入（µm）→ `Units::fromMicrons()` → DBU，**先取整再写入**，绝不把浮点存进模型。
- 拖动位移：鼠标像素差 → µm → DBU → 按网格步长取整；不使用"上次位置 + 增量"的累加浮点。
- 缩放/旋转一个图形：在 `int64` 域算完再 clamp 回 `int32`，越界 → `InvalidEdit`，不做静默截断。
- 网格步长本身也是**整数 DBU**（如 5 nm = 5 DBU @1nm），避免"网格与 DBU 不对齐"导致的漂移。

### 10.2 变换与结构的编辑约束

| 约束 | 原因 |
|---|---|
| 实例的 `mag` 只允许有限位小数（<=1e-6 相对误差），旋转角度保留原始记录值 | 避免每次编辑都累乘产生误差 |
| 阵列（AREF）编辑不得擅自改写成逐个 SREF | 体积会爆炸，且丢失原始语义 |
| 镜像 + 旋转的合成遵循 04 §3 的顺序（mirror → rotate → mag → translate） | 与 GDS/KLayout 一致 |
| `Path` 宽度必须 > 0；`Boundary` 至少 3 点且面积 > 0 | GDS/OASIS 写出时的硬性要求 |
| `Text` 的字符串编码在写回时按 `UNITS`/格式决定（GDS ASCII，OASIS UTF-8） | 避免乱码与不可回读 |

### 10.3 单位变更（Scale Layout）作为独立命令

- 改变 `Units` 会改变全部 DBU 坐标的物理解释；实现方式是**整体缩放所有 cell 的坐标与宽度**，
  不能只改 `units` 字段（否则外部工具读到的尺寸会变）。
- 该操作是一个事务（可撤销），并在执行前提示「将重写所有坐标」。
- 若用户只是想"显示单位不同"，那是视图选项（µm/nm），不碰模型。

### 10.4 与"只读查看"的关系

- 读路径（scene/render）只依赖 `const Layout&`；因此**读写共用一套模型**，
  V1 不暴露写入口即可，不存在"两套数据结构"。
- 一旦某 cell 被标记为只读（例如来自被引用的库文件），编辑工具必须拒绝并说明原因，
  而不是让用户改完之后保存失败。
