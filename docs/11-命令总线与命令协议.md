# 11 命令总线与命令协议（UI 只发命令）

> 本文回答一个问题：**怎样让界面上的每一个操作都变成「发一条命令」，由底层统一执行、记录、可撤销、可脚本化？**
> 结论：新增 `eda::command` 层（**无 Qt**），UI 只构造 `Command` 并调用 `CommandBus::execute()`；
> `CommandBus` 成为唯一的「写入 + 视图变更」入口，内部复用 09 的 `Transaction`/`EditHistory`
> 与 08 的 `EditController` 编排能力。命令的语义仍写在 `editing`，**命令层只做门面**。
>
> 收益不止「解耦」：菜单 / 快捷键 / 工具栏 / 面板 / 视口工具 / 内置控制台 / 插件 / 外部脚本
> 变成**同一条路径**，顺带解决插件 ABI、宏录制、无 GUI 自动化，以及「菜单能做、快捷键不能做」
> 这类长期问题。

---

## 0. 一句话规则

> **UI 不得直接调用 `Document` / `EditController` 的写方法与视图设置方法；一律 `bus.execute(cmd)`。**

用**编译期访问控制**保证（与 09 §4.3 对 `Layout` 的做法一致）：

- `core::Layout` 的写接口只对 `core::Transaction` 开放（已有）。
- `Document::beginTransaction/commit` 只对 `command::ICommandHost` 的实现开放（新增 friend）。
- `DocumentController` 的 `setTopCell/zoomFit/setLayerVisible/setSelection/addMeasure/exportImage`
  改为 `private`，只 `friend` app 层的 `CommandRouter`（新增）。
- `ui/*` 只 include `command/command.h`（命令 ID、参数值类型、结果），**不 include `editing/*`**。

CI 里加一条 grep（与 01 §1 对 `core` 禁 Qt 的做法同构）：

```
# ui/ 下不得出现这些符号：绕过命令总线的旁路
grep -rnE 'EditController|beginTransaction|Transaction\b|setTopCell\(|setLayerVisible\(' src/ui
```

## 1. 为什么值得做（收益 / 代价 / 不做什么）

| 收益 | 说明 |
|---|---|
| 一致性 | 同一动作只有一条实现路径，不存在「菜单走 A、快捷键走 B、面板走 C」 |
| 可测试 | 无 GUI 就能跑「发命令 → 检查 Layout/undo/dump」，命令表驱动生成用例 |
| 可脚本化 | 内置控制台、`--cmd`、`--exec-file`、运行中 socket 全是同一套命令文本 |
| 可审计 | `CommandJournal` 记录「谁在什么时候改了什么」，bug 报告可直接附命令序列重放 |
| 插件 ABI 稳定 | 插件只拿「字符串 + JSON」，不跨共享库边界传 STL 容器（解决 02 §8 的顾虑） |
| 可发现性 | 命令表 + schema 就是 API 文档，控制台可补全、可 `help` |
| 权限收窄 | capability 一处判定（Read/View/Edit/Hierarchy/Boolean/FileSystem），只读文档天然全灰 |

| 代价 | 量级 |
|---|---|
| 新模块 `eda::command`（Bus + Registry + Codec + Journal + 控制台后端） | 约 2–3k 行（含测试） |
| 每条命令的注册样板（spec 行 + codec 行 + handler） | 约 15–25 行；用 `command_table.inc` 表驱动摊销 |
| 参数文本化带来的校验负担 | 每个命令一条「坏参数」用例（表驱动，成本低） |

**明确不做**

1. **不逐帧发命令**：拖动/绘制过程中的预览仍走 `EditOverlay`（09 §5.3），**松手才发一条命令**。
   命令是「一次意图」，不是「一次鼠标事件」。
2. **不做全异步命令总线**：`Layout` 有线程亲和性，命令默认在 GUI 线程同步执行；
   只有 IO 类命令（open/save/export/布尔大运算）异步，返回 `Accepted`。
3. **不替代事务模型**：命令不自己记前像，撤销仍由 `Transaction`/`EditHistory` 负责。
4. **不引入通用反射/自动序列化**：一张显式命令表 + 手写 codec，简单可控、报错信息更好。
5. **不做 TCP 控制端口**：只开本机 Unix domain socket（权限 0600），需要远程就用 ssh 转发。

## 2. 分层位置与依赖

```
                    ┌───────────────────────────────┐
   ui ──────────────▶ app::CommandRouter             │  Qt 适配器：QAction/控制台/socket → Command
   （菜单/快捷键/     │  invoke(id, args)             │
     工具/面板）      └───────────────┬───────────────┘
                                     │ Command
                     ┌───────────────▼────────────────┐
   plugin ──────────▶│ command::CommandBus            │  ★ 唯一执行入口（无 Qt）
   (ICommandSink)    │  execute(Command) → Result     │
   eda --cmd ───────▶│  executeText(line)             │
                     └───┬────────────┬───────────┬───┘
                         │            │           │
             ┌───────────▼──┐  ┌──────▼──────┐  ┌─▼──────────────┐
             │ editing      │  │ core::      │  │ ICommandHost    │
             │ EditOps /    │  │ Transaction │  │ （app 实现：     │
             │ HierarchyOps │  │ EditHistory │  │  文档/场景/选择/ │
             │ SnapEngine   │  └─────────────┘  │  TaskRunner）    │
             └──────────────┘                   └─────────────────┘
```

**依赖规则（追加到 01 §1）**

| 层 | 命名空间 | 依赖 | Qt | 职责 |
|---|---|---|---|---|
| 命令 | `eda::command` | core, editing | ❌ 不依赖 | 命令表、执行管线、参数编解码、命令日志 |

- `command` 不得 include `scene` / `render` / `ui` / `app`；需要「选择集 / 快照 / 状态」时
  通过 `ICommandHost` 抽象（定义在 `command` 里，由 `app` 实现）。
- `ui` 只依赖 `command` 的**公开命令 ID 与参数值类型**，不依赖 `editing` 的实现类型。
- CMake：`eda_command (STATIC) : core + editing`（06 §2 追加）。

## 3. 命令模型

### 3.1 种类与规格

```cpp
namespace eda::command {

enum class CommandClass {
    Query,      // 只读：查选择、查元素、统计、层级依赖
    View,       // 视图状态：相机、顶层、图层显隐/配色、测量、书签（不 dirty 文档、不入撤销栈）
    Edit,       // 改几何/层次：一个命令 = 一个事务 = 一个撤销步
    History,    // undo / redo（本身不可再撤销，但会移动撤销指针）
    File,       // 打开/保存/另存/重载/导出（异步，锁编辑）
};

enum class Capability { Read, View, Edit, Hierarchy, Boolean, FileSystem, Control };

struct CommandSpec {
    std::string_view id;            // 稳定、带版本："edit.selection.move/1"
    CommandClass     cls;
    Capability       capability;
    bool             mutatesLayout;     // 是否需要事务
    bool             undoable;          // 是否产生撤销步
    bool             needsEditingMode;  // 编辑模式打开才允许
    bool             recordInJournal;   // 是否进命令日志（含 View 也行，便于复现）
    std::string_view summary;           // 撤销文案模板："Move {count} elements"
    std::string_view argsSchema;        // 简化 JSON Schema：文档 + 校验 + 控制台补全
};

enum class Origin { Ui, Console, Script, Socket, Plugin, Cli };

enum class DisableReason {          // isEnabled() 的「为什么不能点」，UI 直接显示
    None, NoDocument, ReadOnly, EditModeOff, Locked, WrongDocument,
    NoSelection, Capability, Busy,
};

struct Command {
    std::string   id;
    Args          args;                  // 强类型 variant（见 3.2）
    Origin        origin = Origin::Ui;   // Ui | Console | Script | Socket | Plugin | Cli
    std::string   docToken;              // 外部命令可指定目标文档；空 = 当前文档
};

struct CommandResult {
    enum class Status { Ok, Accepted, Rejected, Failed };
    Status                       status = Status::Ok;
    std::string                  label;          // 实际使用的撤销/日志文案
    std::vector<core::CellId>    dirtyCells;
    std::vector<core::ElementRef> newSelection;  // 例如刚创建的元素
    json::Value                  data;           // Query 的返回值 / Edit 的计数
    core::Error                  error;          // Rejected/Failed 时有效
};

} // namespace eda::command
```

**为什么带版本号**：命令 ID 是**对外 API**（脚本、插件、快捷键配置都可能存下来）。
已发布的 ID 不改名；语义变化就新增 `.../2` 并保留 `/1`（内部转调 + 弃用警告）。

### 3.2 强类型内核 + 文本边界

```cpp
using Args = std::variant<
    std::monostate,
    // view
    view::ZoomFit, view::ZoomToBox, view::SetTopCell, view::SetLayerVisible,
    view::SetLayerColor, view::SetSelection, view::AddMeasure, view::SetGrid,
    // edit（复用 editing 的值类型，见 08 §5.5）
    editing::CreateRequest, editing::MoveRequest, editing::DeleteRequest,
    editing::TransformRequest, editing::InstanceRequest,
    editing::LayerChangeRequest, editing::CellRequest,
    editing::BatchRequest,        // 组合命令：一组子命令，一个事务
    editing::BooleanRequest,      // V2 E3
    // file
    file::OpenRequest, file::SaveRequest, file::ExportRequest>;
```

- **内核强类型**：handler 用 `std::get<T>(cmd.args)`，没有字符串拼写错误；漏处理变体编译期就报。
- **文本只在边界**：`CommandCodec::parse(line) → Command`、`format(Command) → string`，
  只在控制台 / CLI / socket 使用；UI 内部直接构造强类型命令，零解析开销。
- 文本解析用 `eda::json`（`eda_dump --format json` 本来就需要稳定 JSON 输出，06 §5）；
  **不要把 Qt 的 `QJson` 引进 core/command**（保持无 Qt，便于 CLI 与单测复用）。

### 3.3 命令表（一张表定义 API）

`src/command/command_table.inc`：

```cpp
// EDA_COMMAND(Id, Class, Capability, Mutates, Undoable, EditingMode, Summary)
EDA_COMMAND("query.selection.get/1",   Query,   Read,        false, false, false, "Get selection")
EDA_COMMAND("view.camera.zoomFit/1",   View,    View,        false, false, false, "Fit to layout")
EDA_COMMAND("view.topCell.set/1",      View,    View,        false, false, false, "Set top cell {cell}")
EDA_COMMAND("view.layer.setVisible/1", View,    View,        false, false, false, "Set layer visibility")
EDA_COMMAND("edit.shape.create/1",     Edit,    Edit,        true,  true,  true,  "Create {kind} on {layer}")
EDA_COMMAND("edit.selection.move/1",   Edit,    Edit,        true,  true,  true,  "Move {count} elements")
EDA_COMMAND("edit.selection.delete/1", Edit,    Edit,        true,  true,  true,  "Delete {count} elements")
EDA_COMMAND("edit.cell.delete/1",      Edit,    Hierarchy,   true,  true,  true,  "Delete cell {cell}")
EDA_COMMAND("edit.batch/1",            Edit,    Edit,        true,  true,  true,  "Batch of {count} operations")
EDA_COMMAND("edit.undo/1",             History, Edit,        true,  false, true,  "Undo {label}")
EDA_COMMAND("edit.redo/1",             History, Edit,        true,  false, true,  "Redo {label}")
EDA_COMMAND("file.save/1",             File,    FileSystem,  false, false, false, "Save {path}")
```

同一份表被三处包含（X-macro）：

1. `CommandSpec kCommandSpecs[]` —— 注册表、`help`、控制台补全、enabled 判定；
2. `parseArgs(id, json)` / `formatArgs(id, Args)` 的 `switch` 分支骨架（每分支手写 2–5 行）；
3. `test_command_table.cpp` —— 断言「每个 spec 都有 handler、都有样例、都能往返」。

**好处**：命令的增删改都收敛到「一行表 + 一个 handler」，评审看 diff 就知道 API 变了什么。

### 3.4 参数约定（文本形态）

| 概念 | 文本形态 | 说明 |
|---|---|---|
| 元素引用 | `{"cell":"TOP","slot":12,"gen":3,"inst":false}` | 与 `ElementRef` 一一对应；`gen` 不匹配 → 拒绝 |
| 当前选择 | `"@selection"` | 工具手势用它，UI 不必把句柄序列化出去 |
| cell | `"TOP"` 或 `12` | 名字在入口解析为 `CellId`；重名报错；重命名前录的脚本仍可用 |
| 坐标 | `[1000, -2500]`（DBU）或 `"10.5um"` | 后者用文档 `Units` 换算；非整数 DBU 拒绝 |
| 图层 | `{"layer":1,"datatype":0}` | OASIS 命名字段留 `"name":"M1"`（V3） |
| 颜色 | `"#RRGGBBAA"` | 与 `.lyp` 一致 |
| 范围 | `{"box":[[x0,y0],[x1,y1]]}` | 入口统一成 `min/max` 顺序 |

**硬校验**（进入 handler 之前）：坐标 `int32` 范围、多边形 ≥ 3 点、path 宽度 > 0、层存在、
cell 存在、refs 非空、只读模式下禁止写命令、`edit.batch` 子操作数上限（如 10⁵）。

## 4. 执行管线（CommandBus）

### 4.1 接口

```cpp
namespace eda::command {

class ICommandHost {                      // app 层实现；command 层只看到抽象
public:
    virtual ~ICommandHost() = default;

    // ---- 状态 ----
    virtual bool hasDocument() const = 0;
    virtual bool isReadOnly() const = 0;
    virtual bool editingMode() const = 0;
    virtual bool editingLocked() const = 0;          // 保存中 / 长任务中
    virtual core::CellId editTarget() const = 0;
    virtual std::span<const core::ElementRef> selection() const = 0;
    virtual core::Units units() const = 0;

    // ---- 受控能力（只有 Bus 会调用；实现内部再收窄） ----
    virtual core::Result<core::CellId> resolveCell(std::string_view name) const = 0;
    virtual core::Result<void> applyView(const ViewArgs&) = 0;   // 相机/顶层/图层/测量
    virtual core::Result<json::Value> query(const QueryArgs&) = 0;

    // 事务由宿主开启/提交；handler 只拿到事务引用，内部禁止再开事务
    using Body = std::function<core::Result<editing::CommittedEdit>(core::Transaction&)>;
    virtual core::Result<editing::CommittedEdit> withTransaction(std::string label, Body) = 0;
    virtual core::Result<void> undo() = 0;
    virtual core::Result<void> redo() = 0;

    virtual core::Result<void> runFileCommand(const file::Request&,
                                              std::function<void(core::Result<void>)>) = 0;

    // ---- 命令完成后统一收尾 ----
    virtual void afterCommand(const Command&, CommandResult&) = 0;  // 增量重建 + 发信号 + 选择剪枝
};

class CommandBus {
public:
    explicit CommandBus(ICommandHost& host);

    core::Result<CommandResult> execute(const Command& cmd);          // 主线程，同步
    core::Result<CommandResult> executeText(std::string_view line);   // 解析 + execute
    bool isEnabled(std::string_view id, DisableReason* why = nullptr) const;
    const CommandSpec* spec(std::string_view id) const;

    void setJournal(CommandJournal* journal);     // 可为空
    void setPendingLimit(size_t n);               // 重入排队上限，默认 1024
};

} // namespace eda::command
```

> `Transaction` 不可拷贝，所以不作为返回值：`withTransaction` 在宿主内部完成
> 「开事务 → 调 handler → 成功则 commit + `EditHistory::push` / 失败则析构回滚」，
> 并把 `editing::CommittedEdit{dirtyCells, label}` 交回 Bus。handler 里禁止再开事务。

### 4.2 九步管线

```
execute(cmd)
 1. 前置：必须在 GUI 线程（assert）；执行中重入 → 入队（FIFO），返回 `Accepted`，
    完成后由 `CommandRouter::executed` 回投；队列满 → `Rejected{Busy}`
 2. 查表：未知 ID → Rejected{InvalidEdit, "unknown command"}
 3. 能力校验：hasDocument / isReadOnly / editingMode / editingLocked / capability
       → 失败返回 Rejected + DisableReason（UI 用它灰掉菜单）
 4. 引用与参数规范化：
       @selection → 当前选择副本；名字 → CellId；句柄 generation 校验；
       坐标范围/点数/宽度/层存在性校验；批量上限校验
 5. 按 cls 分派：
    Query   : host.query(args) → data（不 dirty、不发场景信号）
    View    : host.applyView(args) → viewDirty/lypDirty（不入撤销栈，与 KLayout 一致）
    Edit    : withTransaction(label, [&](Transaction& txn) {
                  auto r = EditOps::apply(args, txn);       // 语义在 editing
                  if (!r) return r.error();                 // 事务自动回滚
                  return editing::CommittedEdit{ r->dirtyCells, r->newSelection };
              })
    History : host.undo()/redo() → dirtyCells
    File    : host.runFileCommand(...) → Accepted；完成回调再走第 7 步
 6. 失败：事务 RAII 回滚，模型/句柄完全不变；返回 Failed（不进 journal 的 undo 段，但记失败原因）
 7. 成功收尾：host.afterCommand(cmd, result)
        a) SceneUpdater 重建脏 cell（09 §5.1）
        b) 发布新快照（原子指针交换）
        c) 选择集剪枝（失效句柄剔除）+ 应用 newSelection
        d) 发信号：editCommitted / layersChanged / cameraChanged / dirtyChanged
 8. 日志：journal.append(cmdText, result)（含 origin、耗时；失败也记）
 9. 返回 result（外部调用者拿到结构化结果；UI 只在需要时读 data）
```

**关键点**

- **一次命令 = 0 或 1 个撤销步**（`History`/`View`/`Query` 为 0；`File` 不改几何）；
  命令内部禁止再开事务（`Transaction` 以引用传入 handler）。
- **失败不留痕**：任何校验失败都在事务内抛错，回滚由 `Transaction` 析构保证（09 §3.1）。
- **不改模型就不发场景信号**：`View` 命令只触发重绘 / 样式表更新，不动 `dirty`。
- **`Accepted` 不是成功**：`File` 命令返回 `Accepted` 后，UI 用进度条展示，
  结果通过 `CommandRouter::fileFinished` 回来；期间 `editingLocked() == true`。

### 4.3 重入、模态框与长任务

| 场景 | 规则 |
|---|---|
| 命令执行中又收到命令（脚本循环、socket 并发） | 入 FIFO；超过上限拒绝并提示 "busy" |
| 命令需要用户确认（删 cell / 打散体积大） | **UI 先弹框，再发命令**；命令内部禁止 `QDialog::exec()` |
| 保存/导出/布尔大运算 | 走 `TaskRunner`；进入时 `lockEditing()`，完成/取消后解锁 |
| 撤销栈被异步任务移动 | 长任务开始时记录 `historyMark`；完成时若已变则丢弃结果并提示 |
| 文档切换 | 命令带 `docToken`；不匹配 → `Rejected{docChanged}`（脚本不会误改另一个文件） |
| 只读文档 | `Capability` 含 Edit/Hierarchy/Boolean 的命令全部 `Rejected{ReadOnlyDocument}` |
| 编辑模式关闭 | `needsEditingMode` 的命令 `Rejected{InvalidEdit, "edit mode is off"}` |

### 4.4 命令日志（`CommandJournal`）

```cpp
struct JournalEntry {
    uint64_t      seq;
    uint64_t      epoch;        // 文档打开序号（区分不同文件）
    uint64_t      monoNs;       // 相对打开时间
    Origin        origin;
    std::string   text;         // 规范化后的命令文本（可直接重放）
    CommandResult result;       // 状态 + 计数（不存几何）
};

class CommandJournal {
public:
    void append(JournalEntry);
    bool saveScript(const std::filesystem::path&, JournalFilter) const;  // 导出可重放脚本
    std::span<const JournalEntry> entries() const;
};
```

用途（三件事，成本很低）：

1. **Bug 复现**：用户「Export Command Log」，开发者 `eda --exec-file` 重放（含打开文件命令）。
2. **宏录制**：把 `origin == Ui` 的编辑命令导成脚本（V3 脚本功能的雏形）。
3. **审计/回归**：CI 用固定命令序列 + `eda_dump` 对比，替代一部分手工点击测试。

> 注意：日志存的是**命令文本**，撤销仍然用前后像（09 §3.2），**绝不用命令重放做 undo**——
> 否则吸附/对齐结果可能与原状不一致。

## 5. UI 接入（改造成本最低的做法）

### 5.1 `CommandRouter`：Qt 适配器

```cpp
namespace eda::app {

class CommandRouter : public QObject {
    Q_OBJECT
public:
    // 同步；内部把强类型参数交给 CommandBus
    core::Result<command::CommandResult> invoke(std::string_view id,
                                                command::Args args = {});
    core::Result<command::CommandResult> invoke(const command::Command& cmd);  // 工具提交用
    core::Result<command::CommandResult> invokeText(const QString& line);

    bool isEnabled(std::string_view id) const;
    QString disabledReason(std::string_view id) const;
    bool hasActiveDoc() const;
    void reportFailure(const core::Error& err);   // 统一提示（工具/脚本都走这里）

    // 外部来源
    void attachControlSocket(const QString& path);
    void executeScript(const QString& path, bool keepGoing);

signals:
```

### 5.2 QAction：只连命令 ID（不要 30 个手写 connect）

```cpp
// ui/main_window.cpp —— 菜单/快捷键/工具栏共用一张声明式表
struct ActionDef { const char* command; const char* text; QKeySequence shortcut; };

const ActionDef kEditActions[] = {
    {"edit.selection.delete/1", "Delete", QKeySequence::Delete},
    {"edit.selection.copy/1",   "Copy",   QKeySequence::Copy},
    {"edit.selection.paste/1",  "Paste",  QKeySequence::Paste},
    {"edit.undo/1",             "Undo",   QKeySequence::Undo},
    {"edit.redo/1",             "Redo",   QKeySequence::Redo},
};

for (const auto& def : kEditActions) {
    auto* act = new QAction(tr(def.text), this);
    act->setShortcut(def.shortcut);
    connect(act, &QAction::triggered, this, [this, id = def.command] {
        m_router->invoke(id);                 // ← 唯一路径，参数 = 当前上下文
    });
    m_actionById[id] = act;
}
connect(m_router, &CommandRouter::stateChanged, this, [this] {
    for (auto& [id, act] : m_actionById)
        act->setEnabled(m_router->isEnabled(id) && m_router->hasActiveDoc());
});
```

要点：**enabled 状态只由 `CommandRouter` 计算一次**，菜单、工具栏、快捷键、控制台共用，
不会出现「菜单项灰着但快捷键还能触发」。

## 6. 文本协议（让外部「发命令」改底层）

### 6.1 单行命令

```
# 注释行
view.camera.zoomFit
view.topCell.set {"cell":"TOP"}
view.layer.setVisible {"layer":{"layer":1,"datatype":0},"visible":false}
edit.selection.move {"refs":"@selection","delta":[10,0]}
edit.shape.create {"kind":"box","cell":"TOP","layer":{"layer":2,"datatype":0},"box":[[0,0],[100,50]]}
edit.batch {"ops":[
  {"cmd":"edit.shape.create/1","args":{"kind":"box","cell":"TOP","layer":{"layer":2,"datatype":0},"box":[[0,0],[100,50]]}},
  {"cmd":"edit.selection.move/1","args":{"refs":"@selection","delta":[0,200]}}
]}
file.save {"path":"/tmp/out.gds"}
```

规则：`id` + 空格 + 一个 JSON 对象（可省略 = `{}`）；一行一条；`#` 到行尾是注释。
`edit.batch` 是**唯一允许嵌套命令**的形式，整批共用一个事务（失败全回滚），
避免脚本写 20 条独立命令导致 20 个撤销步。

### 6.2 响应（NDJSON，一请求一行）

```json
{"seq":7,"cmd":"edit.selection.move/1","status":"ok","label":"Move 3 elements",
 "dirty":["TOP"],"selection":[{"cell":"TOP","slot":41,"gen":2,"inst":false}],
 "data":{"moved":3},"ms":1.8}
{"seq":8,"cmd":"edit.cell.delete/1","status":"error",
 "error":{"code":"CycleDetected","cell":"B","message":"would create a cycle"}}
```

- `seq` 由客户端提供（可省略），用于并发匹配；`status` = `ok|accepted|rejected|error`。
- `dirty` 用 cell **名字**（脚本可读），不暴露内部 id；`selection` 同时给名字 + 句柄。

### 6.3 四个入口，一套实现

| 入口 | 用法 | 场景 |
|---|---|---|
| 一次性 CLI | `eda --cmd 'view.camera.zoomFit'` | 快速验证、CI |
| 脚本批处理 | `eda --exec-file fixup.txt --save --keep-going` | 批量改版、回归 |
| 运行中 socket | `eda --control-socket` + `eda-cli 'edit.selection.move {...}'` | 与其他工具联动、调试真实界面状态 |
| 内置控制台 | Dock 输入 | 交互式探索/学习命令 |

**socket 设计**

- `QLocalServer`（Unix domain socket）：Linux `$XDG_RUNTIME_DIR/eda-<pid>.sock`，
  macOS `~/Library/Caches/EDA/eda-<pid>.sock`；启动时把路径打到 stdout，便于脚本捕获。
- 权限 `0600`；**默认关闭**，必须 `--control-socket` 显式开启；不监听 TCP。
- 线程：socket 线程只做 `readline + JSON 解析 + 大小校验（≤ 1 MB/行）`，
  再 `QMetaObject::invokeMethod(router, ..., Qt::QueuedConnection)` 投到 GUI 线程执行。
- 背压：单连接未完成请求上限（如 64），超出立刻回 `{"status":"rejected","error":"busy"}`。
- 断连：清空该连接的 pending，不影响文档。

**无界面模式**（CI 与批处理）

`eda --nogui --exec-file s.txt` 用 `QCoreApplication` + `SwRenderer`（或纯 core/io 路径）：
不创建 GL 上下文、不显示窗口，仍走同一个 `CommandBus`（`ICommandHost` 的另一实现）。
这样命令层天然可测，也保证脚本在 GUI / 无 GUI 下行为一致。

## 11. 风险与权衡

| 风险 | 影响 | 应对 |
|---|---|---|
| 命令层变成「第二套模型」 | 双份语义、长期漂移 | 命令只做门面：语义全在 `editing::EditOps`，handler 不超过 30 行 |
| 文本参数校验不严 | 脚本传坏值导致半改 | 入口硬校验 + 每命令一条坏参数用例 + `edit.batch` 整体回滚 |
| 命令 ID 一旦发布难改 | 脚本/插件失效 | 带版本号；弃用走 `/1` → `/2` 转调 + 警告，不直接删 |
| `View` 命令误进撤销栈 | 撤销语义混乱 | `undoable=false` 在表里显式声明；`View` 分支根本不拿 `Transaction` |
| 高频手势被误当成逐帧命令 | 性能崩、撤销栈爆炸 | 明令「松手才发」；overlay 预览路径不变（09 §5.3） |
| 异步 File 命令与编辑交错 | 撤销栈/快照错乱 | `lockEditing()` + `historyMark` 校验 + 文档 token |
| socket 成为安全面 | 本机任意进程改文件 | 默认关闭、0600、仅本机 UDS、`Control` capability |
| 控制台暴露危险命令 | 误删 cell | 无撤销能力的命令（File）在控制台需 `--force`；删除类需 `--yes` |

**一句话总结**：命令层是「入口统一 + 校验 + 记录」的薄门面；事务、撤销、增量更新仍由
`core`/`editing`/`scene` 负责。它把「UI 怎么点」与「底层怎么改」彻底解耦，并顺带把
脚本、插件、自动化、测试都接到同一条路径上。
