# 10 KLayout 功能对齐矩阵

> 用途：把「向 KLayout 看齐」变成**可验收的清单**，避免「像 KLayout」这种无法结项的目标。
> 读法：**KLayout** 列表示该功能在 KLayout 中存在；V1/V2/V3 是本项目的落地阶段；
> 最后一列写差异或取舍理由。`—` 表示该阶段不安排。

图例：✅ 完整实现 ｜ ◐ 部分实现（子集） ｜ ❌ 不做 ｜ `—` 该阶段不安排

平台：仅 macOS + Linux x86_64（不交付 Windows）；下表的对齐目标与平台无关。

## 14. 对齐验收方法（可执行）

1. **同图对比**：同一份 GDS，用 KLayout 与本工具在同一 cell/同一缩放下截图，做像素级 diff
   （容差 2%，抗锯齿差异单列）。覆盖：多边形/路径/文本/阵列/负角度/镜像。
2. **dump 对比**：`eda_dump` 的稳定文本输出 vs KLayout 脚本 dump，
   比较 cell 数、图元数、层号、坐标、mag/angle。
3. **读写往返**：本工具保存 → KLayout 打开 → 再保存 → 本工具打开，dump 必须一致
   （或差异都记在 known-differences 里）。
4. **交互录像**：M1/M2 各录一屏与 KLayout 的对照操作，逐条勾掉 §13 的"待填"。

## 15. 明确不追的能力（写清楚，避免无限扩张）

| 能力 | 不做的理由 |
|---|---|
| 脚本化 DRC 引擎（KLayout `.drc`） | 需要 DSL + 几何引擎 + 多线程执行框架，工作量等同再做一个项目 |
| LVS / 网表提取 / 器件识别 | 依赖工艺器件模型与网表数据库，属于另一个产品 |
| PCell 参数求值（Ruby 定义） | 需要内嵌 Ruby 或重建 PCell 生态；读入按静态图形处理已满足查看/轻度编辑 |
| 3D 视图 / 剖面 | 与 2D 数据模型差异大；V3 之后如需要可做插件 |
| 多用户协同 / 版本管理 | 与单机工具定位不符 |
| 掩模数据准备（OPC、MDP） | 属于下游专业工具 |
