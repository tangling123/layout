# 09 编辑架构与事务模型

> 本文回答一个问题：**在「先查看、后编辑」的产品路线下，怎么让 V1 的查看器不会在 V2 被推翻。**
> 结论：把「可变模型 + 事务 + 稳定句柄 + 增量快照」这四件事在 V1 就钉死，V1 只是**不暴露**
> 编辑入口，代码路径完全一样（读路径不感知可变性）。

---

## 1. 编辑能力分三级（与 10 的功能矩阵对应）

| 级别 | 内容 | 关键依赖 | 阶段 |
|---|---|---|---|
| E0 只读 | 打开、浏览、选择、测量、截图 | 无 | V1 |
| E1 **基础编辑** | 绘制 box/polygon/path/text；移动/复制/删除/旋转/镜像；顶点编辑；实例摆放与阵列；改层号；保存/另存为；撤销/重做 | 事务、句柄、写入器 | V2 / E1–E2 |
| E2 结构编辑 | 新建/删除/重命名 cell；改实例所指 cell；打散（flatten）；层次复制；跨 cell 移动；阵列编辑 | 层次索引、环路检查、bbox 上溯 | V2 / E2 |
| E3 几何运算与检查 | merge / and / or / xor / size；转多边形；编辑检查（自交/零宽/重复/越界） | Clipper2、容差策略 | V2 / E3（**「替代日常改版」的门槛**） |

> 里程碑编号与 07 对齐：V2 分 E1（基础编辑）、E2（保存与层次编辑）、E3（几何运算与检查）、
> E4（交互对齐与硬化）。**E3 不再是 V3 的事**——用户要求能替代日常改版，没有布尔运算与检查就不成立。

**为什么先做 E1 再做 E2**：E1 的每个操作只碰「一个 cell 内的若干图形」，事务与句柄设计
被充分验证；E2 会引入「跨 cell 引用关系变化」，是撤销与增量更新最容易出错的地方，
放在 E1 稳定之后。

## 2. 可变数据模型

### 2.1 容器与句柄

```cpp
namespace eda::core {

using CellId      = uint32_t;    // 稳定，不复用（删除后空洞保留）
using ElementKey  = uint64_t;    // index(32b) | generation(32b)

// 带 generation 的 slot 容器：删除后旧句柄自动失效，不会误改"复用了同一 slot"的新元素
template <class T>
class SlotMap {
public:
    ElementKey insert(T value);                       // 返回新句柄
    T*         find(ElementKey k);                    // generation 不匹配 → nullptr
    const T*   find(ElementKey k) const;
    bool       erase(ElementKey k);                   // 释放 slot，generation++
    template <class F> void forEach(F&& f) const;     // 跳过空洞，缓存友好
    size_t     size() const;                          // 存活元素数
    uint64_t   revision() const;                      // 每次结构变更 +1
};

struct ElementRef {                                   // 跨模块传递的稳定引用
    CellId     cell = kInvalidCell;
    ElementKey key;
    bool       isInstance = false;
};

} // namespace eda::core
```

**为什么不用下标/指针**

| 方案 | 删除后 | 撤销栈 | 选择集 | 插件引用 |
|---|---|---|---|---|
| 下标 | 全部错位 | 失效 | 失效 | 失效 |
| 裸指针 | 悬垂 | UB | UB | UB |
| `shared_ptr<Shape>` | 安全但每图元 16 B + 分配开销 | 可以 | 可以 | 可以 |
| **slot + generation（选用）** | 旧句柄安全失效 | 稳定 | 稳定 | 稳定 |

`shared_ptr` 方案在 10⁷ 图元下多出约 300 MB 且碎片化，因此不用；改为「容器拥有元素、
句柄引用元素」。撤销栈需要「已删除元素的内容」时，直接存**元素副本**（见 §3）。

### 2.2 Cell 与 Layout

```cpp
struct Cell {
    CellId                id;
    std::string           name;
    SlotMap<Shape>        shapes;       // 图形：Polygon / Box / Path / Text / Node
    SlotMap<Instance>     instances;    // 层次引用：Single / Array
    Box                   bboxLocal;    // 本 cell 图形 + 直接子实例的并集
    uint64_t              revision = 0; // 内容版本（任何几何/实例变更 +1）
    std::vector<CellId>   parents;      // 反向引用（由 Layout 维护，用于 bbox 上溯与树展示）
    Properties            props;        // GDS/OASIS 属性（回写保留）
};

class Layout {
public:
    const Units& units() const;
    // ---- 只读访问 ----
    const Cell*  cell(CellId id) const;
    const Cell*  cellByName(std::string_view name) const;
    std::span<const LayerKey> layers() const;

    // ---- 版本与脏追踪 ----
    uint64_t globalRevision() const;
    std::span<const CellId> dirtyCells() const;       // 自上次 clearDirty() 起
    void     clearDirty();

private:
    friend class Transaction;      // 写方法不公开：外部只能经 CommandBus → Transaction 修改

    Result<ElementKey> insertShape (CellId, Shape);
    Result<void>       replaceShape(CellId, ElementKey, Shape);
    Result<void>       eraseShape  (CellId, ElementKey);
    Result<ElementKey> insertInstance(CellId, Instance);
    Result<void>       setInstance (CellId, ElementKey, Instance);
    Result<void>       eraseInstance(CellId, ElementKey);
    Result<CellId>     createCell  (std::string name);
    Result<void>       renameCell  (CellId, std::string name);
    Result<void>       deleteCell  (CellId);          // 仍有引用 → 失败或级联（可选策略）

    std::vector<Cell>              m_cells;           // 或 SlotMap<Cell>（cell 也可被删）
    std::unordered_map<std::string, CellId> m_byName;
    std::vector<LayerKey>          m_layers;
    Units                          m_units;
    std::vector<CellId>            m_dirty;
};
```

**不变量（每次写入后断言，debug 构建全开）**

1. `Cell::parents` 与各 `Instance::target` 双向一致（插入/删除实例时同步维护）。
2. 不允许出现层次环路：插入实例时沿 `target` 向上查，若遇到本 cell → `CycleDetected`。
3. `Cell::bboxLocal` = 「本 cell 图形 ∪ 直接子实例的目标 bbox 变换后」的并集，用于 LOD 剪枝；
   编辑后**沿 parents 上溯重算**（见 §5.1）。
4. `Shape` 的点数、层号在写入时校验；DBU 坐标必须在 int32 范围内。

### 2.3 为什么 `Layout` 不用「整体不可变 + 整体替换」

- 10⁷ 图元的 Layout 深拷贝一次要数百毫秒到秒级，每编辑一次就拷一次完全不可行。
- 渲染侧的隔离靠 `SceneGraph` 快照（只读），不靠 Layout 不可变。
- 「整体替换」只在**打开文件**时发生一次（解析到临时 Layout，成功后 move 进 Document）。

## 3. 事务与撤销

### 3.1 事务模型

```cpp
namespace eda::core {

enum class ChangeKind {
    InsertShape, ReplaceShape, EraseShape,
    InsertInstance, ReplaceInstance, EraseInstance,
    CreateCell, RenameCell, DeleteCell,
    AddLayer, SetLayerName,
};

struct Change {
    ChangeKind  kind;
    CellId      cell;
    ElementKey  key;             // 被改元素
    Shape       shapeBefore;     // 前像（Insert 时为空）
    Shape       shapeAfter;      // 后像（Erase 时为空）
    Instance    instBefore, instAfter;
    std::string strBefore, strAfter;   // 改名/改图层名的旧新值
    // 用"值"而非指针：撤销栈的寿命必须超过元素本身
};

class Transaction {
public:
    explicit Transaction(Layout& layout, std::string label);
    ~Transaction();                        // 未 commit → 自动 rollback
    // 写入转发到 Layout 并记录 Change
    Result<ElementKey> insertShape(CellId, Shape);
    Result<void>       replaceShape(CellId, ElementKey, Shape);
    Result<void>       eraseShape(CellId, ElementKey);
    // ... 其余同 Layout
    Result<void> commit();                 // 成功：压入 EditHistory
    void         rollback();               // 逆序应用前像
    bool         isEmpty() const;          // 空事务不产生撤销步
    const std::string& label() const;
};

} // namespace eda::core
```

**语义约定**

- **一个用户手势 = 一个事务**（拖动松手、按一次删除、粘贴一次…）；对话框类操作可以把多次
  Layout 调用合并到同一事务。落到代码上：**一个命令 = 一个事务 = 一个撤销步**，
  手势在提交时翻译成一条命令（11 §5.4），命令内部不再开事务。
- **事务可嵌套**：内层 `commit()` 只把 Change 追加到外层（便于「批量操作」复用子操作）；
  只有最外层产生一个撤销步。
- **失败即回滚**：任何一个写操作返回错误 → 整个事务作废，UI 报错，模型不变。
- **可重入保护**：同一 Layout 同时只允许一个活动事务；保存 / 场景构建期间禁止开启事务。

### 3.2 撤销/重做

```cpp
class EditHistory {
public:
    void push(std::unique_ptr<Transaction> txn);   // 清空 redo 栈
    bool canUndo() const;  bool canRedo() const;
    Result<void> undo(Layout&);                    // 逆序应用前像
    Result<void> redo(Layout&);                    // 顺序应用后像
    std::string undoLabel() const;  std::string redoLabel() const;

    // 保存点：用于 dirty 标记（撤销回到保存点 → 文档变"干净"）
    void markSaved();      bool isAtSavePoint() const;

    // 资源上限
    void   setMemoryLimit(size_t bytes);   // 默认 512 MB
    void   setStepLimit(size_t steps);     // 默认 200
    size_t memoryUsage() const;
};
```

- **内存上限**：超出时从栈底丢弃最老事务并在状态栏提示「history truncated」；若保存点被丢弃，
  文档永久标记为 dirty（保守策略，避免误判「无修改」）。
- **为什么存前后像而不是重放操作**：「移动 1000 个图形」若存操作，撤销要重算吸附/对齐，
  结果可能与原状不一致；存前后像是**精确还原**，也天然支持排序/合并。
- **几何体积优化**：`Shape` 用 `std::vector<Point>` 直接持有；极端多边形可用
  `shared_ptr<const std::vector<Point>>` + COW。V2 先用值语义，测出内存问题再优化。

### 3.3 脏标记与保存点

- `Document::dirty = !history.isAtSavePoint()`：撤销回到保存点会自动变干净（KLayout 行为）。
- 关闭窗口/退出应用：dirty → 弹「Save / Discard / Cancel」。
- 外部修改检测：`QFileSystemWatcher`；磁盘文件变了且本机也 dirty → 保存时警告覆盖。

## 4. 编辑操作清单（E1/E2）

### 4.1 图形编辑

| 操作 | 事务内动作 | 约束 / 备注 |
|---|---|---|
| 创建 box/polygon/path/text | `insertShape` | 层必须存在；吸附生效；path 宽度 > 0 |
| 移动（含多选） | 对每个 ref `replaceShape`（实例则 `setInstance`） | 位移量按用户网格取整 |
| 复制/阵列粘贴 | 多次 `insertShape` / `insertInstance` | 一次粘贴合并为一个事务 |
| 删除 | `eraseShape` / `eraseInstance` | 删除实例不删除目标 cell |
| 旋转 / 镜像 | `replaceShape`（重算点）或实例变换 | 以选择集 bbox 中心为基准点 |
| 顶点编辑 | `replaceShape`（整条替换） | 至少 3 点；面积为 0 时提示 |
| 改层号 / 改宽度 / 改文本 | `replaceShape` | 属性面板与工具共用同一路径 |
| 批量迁移到新层 | 逐元素 `replaceShape` + `AddLayer` | 一个事务，可整体撤销 |

### 4.2 层次编辑（E2）

| 操作 | 说明 |
|---|---|
| 放置实例 | 从 Cell 树拖入或 "Place Instance" 对话框；先查环路 |
| 阵列编辑 | 修改 cols/rows/间距（三点式 AREF 保留原始向量，见 04 §6） |
| 改实例目标 cell | `setInstance`；两侧 parents 同步更新 |
| 打散（Flatten） | 把选中实例的目标几何复制进当前 cell；**提示体积爆炸**，默认只打散一层 |
| 复制到新 cell | 选区「Make Cell」：新建 cell、移入选中图形、原位放实例 |
| 重命名/删除 cell | 重命名改 `m_byName`；删除前检查引用，或提示「同时删除引用」 |
| 编辑"实例内部" | 语义 = 编辑目标 cell（KLayout 行为）：`Descend` 把目标 cell 设为编辑目标 |

> **关键语义（与 KLayout 一致）**：选择集中出现实例路径时，**编辑对象永远是「cell + 元素」**，
> 不是「这条路径上的那个副本」。否则同一个 cell 会被改出多份不一致的几何。

### 4.3 编辑器层面直接拒绝的操作

- 造成层次环路的实例插入（`CycleDetected`）。
- 目标 cell 只读 / 文档 `readOnly` / `lockEditing()` 期间。
- 坐标超出 int32 DBU 范围（GDS 写入也会失败，提前拦截）。
- 事务之外直接改 `Layout`（写接口只对 `Transaction` 开放，编译期即隔离）。
- **命令之外直接调 `DocumentController` / `EditController`**：UI 只允许
  `CommandRouter::invoke(id, args)`；面板/工具不得自己开事务，否则校验、日志、
  enabled 状态与撤销文案会分叉（11 §0、§8）。

## 5. 增量更新：编辑如何变成新画面

### 5.1 脏 cell 传播

```
Transaction::commit
 -> Layout 记录受影响 cell 到 m_dirty
 -> SceneUpdater::apply(dirtyCells)
      1) 对每个脏 cell 重建 CellGeometry（形状批次 + 实例列表）
      2) 沿 parents 上溯：重算 bboxLocal（几何 bbox ∪ 子实例 bbox 变换）
      3) 生成新 SceneGraph（浅拷贝 map，只替换脏条目）
      4) 原子发布 -> emit sceneChanged
```

- 只有**形状**变化：只重建该 cell；父 cell 的 `CellGeometry` 不变，但 bbox 可能变（影响剪枝），
  上溯只更新 bbox，不重建顶点。
- **实例**变化：父 cell 的 `CellGeometry`（实例列表）必须重建；同时更新两侧 parents。
- 一次多选编辑跨 N 个 cell → 一次发布（不要每个元素发布一次）。

### 5.2 大 cell 的处理

| 被改 cell 图元数 | 策略 |
|---|---|
| ≤ 2×10⁴ | 同步重建（< 8 ms），松手即刷新 |
| 2×10⁴ … 5×10⁵ | 同步重建 + **分帧上传**（顶点缓冲分块，首帧先画已有部分） |
| > 5×10⁵ | 后台重建 + 期间显示「旧几何 + 预览叠加层」，完成后切换并提示耗时 |

### 5.3 交互期预览（ghost）

- 拖动/绘制期间**不改模型**：`EditTool` 把「当前候选几何」交给 `OverlayPainter`，
  用高亮色直接画（QPainter 或 GL 线段），与几何重建完全解耦。
- 优点：拖动 60 FPS 与 cell 大小无关；取消（Esc）零成本；不需要「临时修改 + 回滚」。
- 松手才 `Transaction` + 增量更新；提交失败则叠加层消失、模型未变。

### 5.4 选择集与快照的关系

- `SelectionSet` 存 `ElementRef`（cell + key），**不存快照指针**。
- 快照切换后，选择集用 `Layout::cell()` 解析为「当前元素」；元素已被删除则自动剔除并上报
  `selectionPruned` 信号。
- 高亮绘制：从选择集解析出元素**当前**几何 → 生成高亮批次（不依赖旧快照）。

## 6. 工具状态机与吸附

### 6.1 工具协议

```cpp
namespace eda::ui {

class IEditTool {
public:
    virtual ~IEditTool() = default;
    virtual void activate(const ToolContext&) = 0;      // 相机、捕捉设置、编辑目标 cell
    virtual void deactivate() = 0;
    virtual bool mousePress  (const ToolEvent&) = 0;     // 返回 true = 已消费
    virtual bool mouseMove   (const ToolEvent&) = 0;
    virtual bool mouseRelease(const ToolEvent&) = 0;
    virtual bool keyPress    (const ToolEvent&) = 0;     // Esc 必须取消
    virtual void paintPreview(render::OverlayPainter&) const = 0;
    virtual std::string statusHint() const = 0;          // "Click first corner"
};

} // namespace eda::ui
```

工具不直接改 `Layout`：它产生 `editing::OperationRequest`（例如 `MoveRequest{refs, delta}`），
由 `EditController` 开启事务并执行 —— 鼠标工具、菜单命令、脚本共用同一条写入路径。

### 6.2 吸附（SnapEngine）

优先级（高 → 低）：**元素顶点 → 元素边/中点 → 实例原点 → 用户网格 → 1 DBU**。

- 搜索半径 = `max(6 px, 用户网格/2)` 换算成 DBU；用 cell 的空间索引做范围查询
  （与拾取共用，见 05 §5）。
- `Shift` 约束正交/45°；`Ctrl`（macOS `Cmd`）临时关闭吸附；网格步长在状态栏可切换
  （1 / 5 / 10 / 100 DBU 及自定义）。
- 吸附结果同时写入**状态栏坐标**与预览绘制，保证「看到的位置 = 提交的位置」。

### 6.3 编辑目标与只读保护

- `Document::editTarget`：默认当前顶层 cell；`Descend` 可切到子 cell；视口角标常显
  "Editing: TOP"，避免误改。
- 只读来源：文件系统只读、用户显式只读、`lockEditing()`（保存中）、cell 只读标记（V3）。

## 7. 保存与写入器

### 7.1 保存策略

`Cmd+S` = **原地覆盖**（用户确认要直接存档，不是「只能另存为」）；`Cmd+Shift+S` = 另存为。

| 场景 | 行为 |
|---|---|
| Save（默认） | 同格式原子覆盖：同目录临时文件 → `fsync` → 原文件复制为 `.bak` → `rename` |
| Save 但格式不可写 | 只读格式（如某些只读导入格式）→ 自动转 Save As，并说明原因 |
| Save 但路径不可写 | 权限/只读挂载 → 错误对话框 + 立即转 Save As |
| Save As | 选格式与路径；换格式时提示「可能丢失格式特有属性」 |
| 保存前 | 比对 `(mtime, size, inode)`；不一致 → 冲突对话框：Overwrite / Save As / Reload / Cancel |
| 保存中的编辑 | `lockEditing()`，编辑工具栏置灰；进度可取消（取消 → 删除临时文件） |
| 保存后 | `history.markSaved()`；`lypDirty=false`；刷新 FileStamp；**写盘校验通过**才切 dirty |
| 崩溃/断电 | 打开或启动时扫描 `<target>.tmp-*` → 提示恢复，恢复成功后删除残留 |
| `.lyp` 写失败 | 只告警（几何已落盘），保持 `lypDirty`，下次保存重试；写前留 `.lyp.bak` |

**保存顺序**：几何 → `.lyp`（若 dirty）→ `.eda.json`（视图状态）。三段各自原子写，
但只有几何失败会整体回退；后两者失败只降级为「属性没存上」的警告。

### 7.2 写入器要点（GDS）

- 单位：`UNITS` = (dbuPerUserUnit, metersPerDbu) 由 `Layout::units()` 反算，保证读回一致；
  用户改单位属于独立命令（会缩放全部坐标）。
- cell 顺序：按**依赖拓扑序**写出（被引用者在前，GDS 惯例）；同一 cell 只写一遍。
- 记录：`BOX` / `BOUNDARY` / `PATH` / `SREF` / `AREF` / `TEXT` / `NODE`（原样保留）/ `PROPATTR`。
- 多边形超过 8191 点：GDS 限制单条 BOUNDARY 点数，需**切分**；写前给出警告。
- 非几何记录（`NODE`、未知记录）：读入时以 `RawRecord` 保留，写出时按原顺序输出。

### 7.3 写入器要点（OASIS）

- 写 `START`/`END`/`CELL`/`PLACEMENT`/`RECTANGLE`/`POLYGON`/`PATH`/`TEXT`/`PROPERTY`；
  `END` 后写 offset table（可选，但能显著加速下次打开）。
- CBLOCK：大文件默认开启（zlib deflate），与 reader 共用压缩层。
- modal 变量：**每个 cell 开头重置**，避免跨 cell 污染；`REPETITION` 只作用于紧随其后的元素。
- 坐标 delta：V2 写绝对坐标（简单可靠）；delta 作为 V3 的体积优化。

### 7.4 写入后的自检（必须做）

1. 计数对比：读写前后 cell 数、各 cell 图元数、实例数一致。
2. 结构对比：`eda_dump` 文本化后 diff（顺序、层号、坐标、mag/angle）。
3. 往返一致：同一文件「读 → 写 → 读」后 dump 必须完全相同。
4. 用 KLayout 打开写出结果并截图对比（人工/黄金图）。

### 7.5 图层属性写回（`.lyp`）

- **权威格式**：`<file>.lyp`（KLayout XML）。`.eda.json` 只存顶层 cell、相机、标尺、书签。
- **保留未知内容**：读入时保存原始 XML DOM；写回只改目标节点的值，其它元素/属性/注释原样输出。
  这是为了避免「用本工具存一次，工艺厂的自定义层字段全丢」。
- **不凭空创建**：文件旁没有 `.lyp` 且用户没改过图层属性时，保存**不生成** `.lyp`；
  用户显式 `Save Layer Properties...` 才创建。
- **不进撤销栈**：颜色/显隐/顺序属于视图状态（与 KLayout 一致），改动只置 `lypDirty`。
  但「改层号」是几何编辑，**必须**走事务与撤销（两者不要混为一谈）。
- **与几何一起保存**：`Cmd+S` 时若 `lypDirty`，先原子写 `.lyp` 再报「保存成功」；
  大 `.lyp`（> 5 MB，层数上万）要显示进度；写前留 `<file>.lyp.bak`。

## 8. 编辑检查与布尔运算（V2 E3 交付）

- **布尔运算**：引入 Clipper2（整数坐标、Boost 许可），封装在 `editing::BooleanOps`，
  输入输出都用 DBU 整数以避开浮点边界问题；支持 merge / and / or / xor / size。
  大结果（> 10⁴ 输出图元）分块插入事务，保证进度与取消可用。
- **编辑检查**（KLayout "Layout > Check" 的子集）：自交/退化多边形、零宽 path、重复图形、
  越界、非网格对齐；最小宽度/间距需要规则输入（可选）。结果进「问题面板」，双击定位。
- **不打散也能用**：布尔运算默认在**当前编辑 cell 内**进行，不改层次结构；
  「打散后再布尔」是用户显式选择的组合命令。
- **不做**：完整的 DRC 语言/规则引擎（见 README §6）。

## 9. 与 KLayout 的行为对齐（编辑相关）

| 行为 | KLayout | 本项目 | 说明 |
|---|---|---|---|
| 编辑模式开关 | 有（Edit Mode） | 有（工具栏 + `E`） | 关闭时隐藏全部编辑入口，防误改 |
| 编辑目标 cell | 当前 top cell，可 Descend | 同 | 状态栏常显 "Editing: CELL" |
| 编辑实例内部 | Descend / 双击进入目标 cell | 同 | 绝不"就地改这个副本" |
| 移动基准 | 拖动最近顶点/边，或按网格 | 同 + 显式基准点选项 | 差异登记在 known-differences |
| 撤销粒度 | 每个手势一步 | 同 | 事务边界 = 手势边界 |
| 保存 | 原地覆盖 + 备份 | **默认原地覆盖** + `.bak` + 外部修改检测 | 见 §7.1；冲突必须弹窗 |
| 图层属性保存 | `.lyp` 侧车 | 同（权威格式，保留未知字段） | 见 §7.5 |
| 保存时格式 | 保持原格式 | 同（换格式只能另存为） | 见 §7.1 |
| 阵列编辑 | 保留 AREF 向量 | 同 | 不擅自转成逐个 SREF |
| 图层操作 | 拖图层改层号、右键批量 | 同 | 图层表变更也要走事务 |

## 10. 性能与内存预算（编辑态）

| 项 | 预算 | 说明 |
|---|---|---|
| 单次事务开销（1e4 元素） | ≤ 20 ms | 主要是前后像拷贝 |
| 撤销栈内存 | ≤ 512 MB（可配） | 超出截断最老事务 |
| 元素句柄 | 8 B | `ElementKey`，不随元素数增长 |
| 选择集 | 1e5 元素 ≈ 1.6 MB | `ElementRef` 16 B（含 padding） |
| 增量重建（1e5 图元 cell） | ≤ 60 ms | 超标走后台重建 |
| 保存 1 GB GDS | ≤ 30 s | 顺序写；SSD 上主要受 CPU 压缩限制 |

## 12. 风险与未决

| 风险 | 影响 | 应对 |
|---|---|---|
| 撤销栈存前后像导致内存增长快 | 大范围布尔/打散可能吃 GB | 上限截断 + 大操作提示；必要时改「操作重放 + 校验」 |
| 大 cell 同步重建卡 UI | 松手后 100 ms 级卡顿 | 分帧上传 / 后台重建 / 明确提示 |
| parents 维护遗漏 | 崩溃或 bbox 错误 | 不变量断言 + 属性测试 |
| OASIS 写出兼容性 | 第三方工具读不了 | 以 KLayout 做回归；保守写出（不用高级压缩特性） |
| Clipper2 坐标范围 | int32 溢出 | 输入前范围检查，必要时平移到局部原点再运算 |
| `.lyp` 写回破坏工艺厂字段 | 层定义失效、下游工具读错 | 原始 DOM 就地改值 + 未知元素保留 + 往返测试 + `.lyp.bak` |
| 原地保存覆盖外部改动 | 数据丢失 | `(mtime,size,inode)` 检测 + 冲突弹窗 + `.bak` + 残留 tmp 恢复 |
| 与 KLayout 编辑语义差异 | 用户迁移困惑 | 逐条登记 known-differences，优先修正高频路径 |
