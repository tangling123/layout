# 07 路线图、验收标准与风险

> 路线：**先看（V1）→ 再改（V2）→ 后分析/对齐（V3）**。
> 里程碑按「可演示」切分，不按模块切分；每个里程碑结束都能给人演示。

---

## 1. 里程碑（V1 查看）

### M0 — 骨架可运行（约 1 周）

| 交付 | 验收标准 |
|---|---|
| CMake 工程 + presets + 空主窗口 + 深色主题 | `cmake --preset mac-debug`（或 `linux-debug`）配置通过；`eda` 启动无警告 |
| `core` 基础类型（Point/Box/Transform/Units/Result）+ **SlotMap + Transaction** | 单测覆盖单位换算、变换合成、句柄失效、事务回滚 |
| `eda_dump`：顺序打印 GDS 记录 | 能打印任意小 GDS 的记录序列，不崩溃 |
| 日志分类 + 设置读写 | `QT_LOGGING_RULES` 生效；重启记住窗口布局 |

> 可变模型的地基（SlotMap/Transaction/EditHistory）在 M0 就写，**V1 不暴露编辑入口**。
> 这一周的成本换来 V2 不必重写渲染、选择、缓存（见 09 §2.3）。

### M1 — 打开并显示 GDS（约 2 周）

| 交付 | 验收标准 |
|---|---|
| `GdsReader`（结构/图元/层/文本/属性） | 样例文件图元数与 KLayout 一致（±0） |
| `SceneBuilder`（暂不展开层次，只读顶层 cell + 一层 SREF） | 显示正确，无坐标错位 |
| `SwRenderer` + `Camera2D` + 网格 | 缩放到 1 nm 精度仍对齐；`zoomAt` 定点 |
| 图层面板（显隐/改色）+ 状态栏坐标 | 勾选即时生效 |
| 打开进度 + 取消 | 取消后无残留状态 |
| **命令层骨架**（`command::CommandBus` + 3 条 view 命令 + `CommandRouter` 动作表） | 缩放/顶层/图层开关全部经 `invoke(id)`；菜单与快捷键 enabled 同源（11 §10 S0–S1） |

**M1 的核心价值**：把「坐标/单位/变换」这条最容易错的主干验证透。

### M2 — 层次、选择、单元树（约 2 周）

| 交付 | 验收标准 |
|---|---|
| SREF/AREF 完整展开 + 循环/缺失检测 | 3 个层次样例与 KLayout 逐点一致 |
| 单元树面板（懒展开）+ 实例树（parents） | 10⁵ 实例的 AREF 不卡死（规模假设见 README §1） |
| 选择 + 属性面板 + 高亮 | 点击命中与视觉一致；属性显示 `cell + key` 与路径 `TOP/A/B#3` |
| 顶层单元切换 + 适配窗口 | 切换后 < 1 s 完成 |

### M3 — OpenGL 渲染 + 性能（约 3 周）

| 交付 | 验收标准 |
|---|---|
| `GlRenderer`：批处理 + 逐层 draw + 实例化 | 10⁶ 可见图元 ≥ 30 FPS |
| LOD（盒子/几何/递归 + 滞回） | 全图 fit 首帧 ≤ 2 s；缩放无闪烁 |
| 空间索引 + CPU 拾取 | p95 ≤ 30 ms |
| 显存 LRU（键含 geometry 指针/revision） | 连续平移 10 min 显存不增长 |
| `--bench` 输出 JSON | 指标可回归比较 |

### M4 — OASIS + 导出（约 3–4 周，可与 M3 并行）

| 交付 | 验收标准 |
|---|---|
| varint/字符串/实数/表格 | 编解码往返单测全绿 |
| CELL/PLACEMENT/几何记录 + modal/delta | 与 KLayout 渲染一致（截图对比） |
| CBLOCK（deflate） | 压缩样例正确解析 |
| REPETITION 全类型 | 每种类型一个用例，逐实例断言 |
| 导出 PNG / SVG | 与屏幕一致（含叠加层可选） |

### M5 — 测量与体验完善（约 2 周）

| 交付 | 验收标准 |
|---|---|
| 测量工具（吸附、面积、角度）+ 面板 | 测量值可复制；`Esc` 取消 |
| `.lyp` 图层属性读写（**V1 就做**，保留未知元素） | 与 KLayout 的层色一致；改一个颜色再写回，未知元素与其它字段均保持（允许缩进/空白差异） |
| 最近文件、拖放打开、快捷键（英文 UI） | macOS/Linux 快捷键行为正确 |
| 消息面板（警告跳转） | 坏文件可定位到偏移 |

### M6 — 硬化与 V1 发布（约 2 周）

| 交付 | 验收标准 |
|---|---|
| 双平台 CI（macOS + Linux）+ ASAN + 黄金图 | 主干全绿 |
| 打包（dmg / AppImage） | 干净机器可运行 |
| 文档（用户手册 + 已知差异清单） | 新用户 10 分钟能上手 |

**V1 工期估算**：单人全职约 3.5–4 个月到 M4，5 个月到可发布；两人并行（IO+渲染）可压到约 3 个月。

## 2. 里程碑（V2 编辑）

### E1 — 基础编辑（约 3 周）

| 交付 | 验收标准 |
|---|---|
| 编辑模式开关、编辑目标 cell、只读保护 | 关闭编辑时无任何写入路径可达 |
| `EditController` + 事务提交 + 增量快照（SceneUpdater） | 一次拖动提交到画面更新 ≤ 100 ms |
| **edit 命令接入**：工具/菜单/属性面板全部 `invoke(id)`；`edit.undo/redo` 走命令；控制台可改几何 | `ui/` 无旁路（CI grep）；每条 undoable 命令有 undo 还原用例（11 §9） |
| 创建 box/polygon/path/text、删除、移动、复制、粘贴 | 每个手势一步撤销；失败不留痕 |
| 顶点编辑、改宽度/文本/层号（属性面板可编辑） | 修改后属性面板与画面同步 |
| 撤销/重做 + 编辑历史面板 + dirty 标记 | 撤销回到保存点后标题栏去掉 `*` |
| 吸附（顶点/边/实例原点/网格）、角度约束 | 预览位置 = 提交位置（逐像素一致） |

**E1 的验收硬指标**：随机 100 步编辑后全撤销，`eda_dump` 与初始文件逐字节一致。

### E2 — 保存与层次编辑（约 3 周）

| 交付 | 验收标准 |
|---|---|
| `GdsWriter` / `OasisWriter` + Save / Save As + 原子覆盖 | 读→写→读 dump 一致；写入失败原文件完好 |
| 放置实例 / 阵列 / 改实例目标 cell / 环检查 | 环路被拒绝且提示清晰 |
| 新建/重命名/删除 cell、Make Cell、单层打散（全层见 E3） | 层次不变量测试全绿 |
| 保存期间锁定编辑 + 进度/取消 | 取消后无临时文件残留 |
| 外部修改检测 | 磁盘变更时提示，不静默覆盖 |

### E3 — 几何运算与编辑检查（约 3 周）

| 交付 | 验收标准 |
|---|---|
| `BooleanOps`（Clipper2）：merge / and / or / xor / size | 与 KLayout 结果面积/顶点数一致（容差内）；自交输入不产生非法多边形 |
| 打散（单层/全层）、多边形 ↔ path 互转 | 打散后图元数与 bbox 正确；层归属正确 |
| `EditCheck`：自交/零宽/重复/越界/非网格对齐 + 问题面板 | 坏样例全部检出，双击可定位 |
| 大结果分块提交 + 进度/取消 | 10⁴ 图元 union 不冻 UI；取消后模型完全回滚 |

> **E3 是「能替代日常改版」的门槛**：没有布尔运算与检查，改版仍得回 KLayout。

### E4 — 交互对齐与硬化（约 3 周）

| 交付 | 验收标准 |
|---|---|
| 图层操作（改层号、批量迁移、克隆到新层） | 走事务，可整体撤销 |
| 属性/文本/阵列的高级编辑、多选批量变换 | 与 KLayout 行为逐条对照（10 §13） |
| 大 cell 分帧上传 + 后台重建 | 2×10⁵ 图元 cell 提交 ≤ 250 ms 且 UI 可响应 |
| 编辑相关快捷键与工具栏 | 与 10 §13 实测表一致 |
| 编辑态性能/内存回归 + 崩溃恢复 | 基准无退化；残留 `.tmp-*` 能提示恢复 |

**V2 工期估算**：约 11–12 周（单人）。E1/E2 是必做主路，E3 给几何库接入留缓冲，
E4 可与 E3 部分并行。

## 4. 每个里程碑的「完成定义」（DoD）

1. 功能可演示（有固定样例与步骤）。
2. 新增逻辑有单测；解析/坐标/事务相关的必须有断言。
3. 无新增编译警告；ASAN 无报错；编辑相关跑 TSAN 场景（快照发布）。
4. 相关设计文档已更新（接口变更必须回写 08）。
5. 性能不退化（有 benchmark 记录的对比）。
6. 编辑类里程碑额外要求：**撤销全还原**与**写入往返**测试通过。

## 5. 风险表

| # | 风险 | 概率 | 影响 | 缓解措施 |
|---|---|---|---|---|
| R1 | OASIS 规范细节多（modal/delta/REPETITION/表格），易出隐性错 | 高 | 高 | 独立里程碑；每记录一测试；与 KLayout 截图对比；先支持常见子集并明确提示 |
| R2 | AREF 摆放语义与其它工具不一致 | 中 | 高 | gdstk 生成已知用例 + KLayout 对照；结论写进测试注释 |
| R3 | 大坐标 `float` 抖动 | 中 | 中 | 相机相对坐标 + 局部坐标顶点 + CPU 端 double 模型矩阵（05 §1），M3 前实现 |
| R4 | 病态数据（超深层次、超大单 cell）导致卡死/爆内存 | 中 | 高 | 深度/图元/实例上限 + 折叠 + 提示；构建任务可取消。**不做**百万级 AREF 优化（README §1 规模假设） |
| R5 | macOS OpenGL 弃用；Linux GL 驱动差异 | 中 | 中 | `IRenderer` 隔离；V2+ 切 `QRhiWidget`(Metal)；Linux 用 GL 4.1 基线 + `SwRenderer` 兜底 |
| R6 | UI 与后台线程共享状态导致偶发崩溃 | 中 | 高 | 快照不可变 + 只传值；Layout 只在主线程改；ASAN/TSAN 定期跑 |
| R7 | 三角化性能/退化多边形 | 中 | 中 | 矩形快速路径 + 耳切 + 退化丢弃；面积过小直接画盒子 |
| R8 | 撤销栈存前后像导致内存增长快 | 中 | 中 | 上限截断 + 大操作提示；必要时改「操作重放 + 校验」 |
| R9 | 编辑引入层次不变量错误（parents/环路/bbox） | 中 | 高 | 不变量断言 + 属性测试 + 环路构造用例 |
| R10 | 大 cell 提交后同步重建卡 UI | 中 | 中 | 分帧上传 / 后台重建 / 状态栏提示（09 §5.2） |
| R11 | GDS/OASIS 写出兼容性差（第三方读不了） | 中 | 高 | 保守写出 + 读→写→读 dump 一致 + KLayout 回归 |
| R12 | 编辑语义与 KLayout 有差异，用户迁移困惑 | 中 | 中 | 逐条登记 known-differences；优先修正高频路径 |
| R13 | 图层配色与工艺厂规范不符 | 中 | 低 | 支持 `.lyp`/CSV 导入；颜色错误不影响几何正确性 |
| R14 | 范围膨胀（想一次做成 KLayout） | 高 | 高 | 以 10 的功能矩阵与 §1–§3 阶段为准；V3 之外的能力明确写"不做" |
| R15 | 写 `.lyp` 时丢掉工艺厂自定义字段 | 中 | 中 | 未知 XML 元素/属性原样保留 + 往返测试（06 §4.2 第 19 条）；写前备份 `.lyp.bak` |
| R16 | 原地覆盖把别人的改动冲掉 | 中 | 高 | 保存前比对 `(mtime, size, inode)`；冲突必须弹窗；默认留 `.bak`；残留 `.tmp-*` 可恢复 |
| R17 | 跨平台差异（字体、DPI、路径大小写） | 中 | 低 | 双平台 CI；黄金图只在 macOS；路径/名称比较显式处理大小写；分数缩放纳入测试 |
| R18 | 命令层沦为「第二套模型」或出现旁路调用 | 中 | 高 | 命令只做门面（handler ≤ 30 行）；`Layout`/`Document` 写接口编译期私有；CI grep + code review；新功能先加命令 ID（11 §10 DoD） |
| R19 | 命令文本协议演进不兼容 | 中 | 中 | ID 带版本号；`/1` 保留转调；协议加 `proto` 字段；控制台/grep 用例覆盖旧脚本 |

## 6. 已确认的方向与剩余问题

已在 README §7 记录（v0.4）：

| 问题 | 结论 |
|---|---|
| 用途与编辑强度 | 查看为主，V2 起要**能替代日常改版**（含布尔运算、打散、编辑检查） |
| 保存 | **默认原地覆盖**（原子写 + `.bak` + 外部修改检测 + 崩溃恢复），另存为是次要路径 |
| 图层属性 | 复用并写回工艺厂 `.lyp`（KLayout 兼容），V1 即读写 |
| 规模 | 无百万级 AREF；按 README §1 的规模假设设计 |
| 界面 | 英文 |
| 平台 | macOS + Linux x86_64；**不交付 Windows** |
| 修改入口 | **UI 只发命令**：`ui → CommandRouter → CommandBus → editing`，`eda::command` 无 Qt 依赖；命令文本协议给控制台/脚本/socket/插件用（11、README D16） |

仍待确认（不阻塞开工）：

1. 可用的**真实版图样例**（做性能基线与 KLayout 截图对齐）；涉密则用 gdstk 合成样例。
2. Linux 交付是否只要 AppImage，还是同时要 deb / 源码构建说明。

## 7. 建议的下一步（设计 → 实现的切入顺序）

1. 冻结 [08-接口草案](08-接口草案.md) 的核心接口：`FormatReader/Writer`、`core::Layout`（含写接口）、
   `Transaction/EditHistory`、`SceneGraph`、`IRenderer`、`DocumentController`、`EditController`、
   `command::CommandBus/CommandCodec`、`TaskRunner`、`io::LayerMap`（`.lyp`）。
2. 按 M0 建 CMake 骨架 + 双平台 presets（`mac-*` / `linux-*`）+ 4 个可运行目标
   （`eda`、`eda_dump`、`test_gds_real`、`test_slotmap`）。
3. 按 M1 打通「GDS → Layout → 场景 → 相机 → 屏幕」；此时即可用 V1 演示。
4. V1 稳定后按 E1 加编辑（事务/工具/撤销），E2 加写入器、原地覆盖保存、层次编辑，
   E3 接 Clipper2 做布尔与检查（「替代日常改版」的门槛），E4 收交互与性能。
5. 每个里程碑结束更新 [10](10-KLayout功能对齐矩阵.md) 的状态列与 [known-differences](known-differences.md)。
