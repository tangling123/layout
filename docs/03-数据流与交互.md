# 03 数据流与交互

> 本文用「时序」把模块串起来：谁先调谁、传什么、失败怎么办。
> 箭头 `->>` 表示同步调用，`-->>` 表示信号/回调，`..>` 表示异步（跨线程）。

---

## 1. 启动流程

```
main()
 -> QApplication
 -> app::Logging::init()                 // 分类日志、崩溃处理
 -> app::Settings::load()                // QSettings
 -> app::Application::run()
      -> 建 TaskRunner / EditHistory / PluginManager
      -> 建 DocumentController
      -> 建 command::CommandBus + app::CommandRouter（命令入口，见 11）
      -> ui::MainWindow(DocumentController, CommandRouter)
           -> 建 LayoutView(OpenGL) —— initializeGL 在首次 show 后触发
           -> 建各 Dock 面板并 connect 信号
      -> 恢复 geometry/state、最近文件菜单、主题
      -> show()
      -> 若命令行给了文件路径 -> CommandRouter::invoke("file.open/1", {path})
```

要点：**没有文件时也要有可用的空状态**（视口显示网格 + 提示文字）。

## 2. 打开文件（最核心的流程）

```
用户 Cmd+O
 -> MainWindow -> DocumentController::openFile(path)
    -> io::FormatRegistry::sniff(path)          // 后缀 + 魔数
    -> 若已有文档：询问「替换 / 新窗口打开 / 取消」
    -> TaskRunner::run("open", ...)  ---------- IO 线程 ----------
         -> FormatReader::open(path)
         -> reader.read(layout, options, progress)   // 写入临时 Layout
              loop: 每 64KB -> progress(doneBytes) --queued--> 进度UI
              取消标志被置位 -> 返回 Error{Cancelled}
         -> 得到 Layout（含 stats / warnings）
    <-- queued: onDone(Result<Layout>) -------- 主线程 ----------
    -> 失败：错误对话框（code + offset + 文件名），保持原文档不变
    -> 成功：
         -> new Document(std::move(layout), path)   // 此后 Layout 归 GUI 线程独有
         -> 选顶层单元：侧车记录 > 用户设置 > 文件中第一个 cell
         -> SceneBuilder（异步，快照 A：只算包围盒/节点树，粗粒度）
         -> publish 快照 A -> LayoutView 立即能画（整体轮廓）
         -> 继续构建细粒度 CellGeometry（快照 B）
         -> publish 快照 B -> 重绘，状态栏更新统计
         -> 图层表模型 reset（一次性填充）
         -> 单元树模型 reset
         -> 相机 zoomFit()
         -> RecentFiles::add(path)
         -> 文件不可写 -> document->setReadOnly(true)（编辑入口置灰）
```

**失败/边界**

| 情况 | 行为 |
|---|---|
| 格式无法识别 | `UnknownFormat` + 「查看支持格式」帮助链接 |
| 文件被占用 / 无权限 | `PermissionDenied`，不进入加载 |
| 打开过程中取消 | 释放 Layout，UI 恢复原状态，不写最近文件 |
| 已有大文件打开 | 允许（多文档），但并发加载数限 1（排队） |
| 加载超时（默认 600 s） | 提示但仍可取消，不自动终止 |

**为什么要两阶段快照 A/B？**
10⁷ 图元的几何归一化需要几秒；先把「层次 + 包围盒」发布出去，用户立刻能看到整体形状
并开始缩放/平移，几何在后台补齐——这是「首屏 2 秒」指标的实现方式。

## 3. 一帧的渲染循环（稳态）

```
（由 输入事件 / 快照发布 / 定时器 触发）
LayoutView::requestRepaint()  --合并-->  update()
 -> LayoutView::paintGL()
    -> snapshot = document->snapshot()            // shared_ptr，无锁
    -> renderer->sync(snapshot, styles, camera)   // 仅上传脏 chunk 到 GPU
    -> FrameComposer::draw(renderer, snapshot, camera, overlays)
         1) 清屏
         2) renderer->renderLayout(...)          // 遍历 SceneGraph，LOD 决定细节
         3) renderer->renderHighlight(selection)
         4) QPainter: 网格 / 标尺 / 测量 / 文本 / **编辑预览** / 光标
    -> FrameStats::endFrame()
```

**帧内禁止**：分配大对象、解析、加锁等待构建线程、读磁盘。
目标：CPU ≤ 8 ms/帧（60 FPS 时给 GPU 与合成留余量）。

## 4. 相机交互（平移/缩放）

```
中键按下（或 空格+左键）
 -> LayoutView -> PanTool::mousePress -> 记录起点世界坐标
鼠标移动
 -> PanTool::mouseMove -> camera.panByPixelDelta(dx,dy)
 -> emit cameraChanged()        // 频率高，仅用于状态栏
 -> requestRepaint()            // 合并到下一帧
鼠标释放 -> PanTool::mouseRelease -> 收尾

滚轮
 -> camera.zoomAt(screenPos, factor)      // 以光标为不动点
 -> requestRepaint()
```

- 相机变更**不触发**场景重建；只有「跨过 LOD 阈值 / 有新 cell 首次可见」时，
  渲染层才向场景层请求补齐（惰性上传）。
- 平移进入未上传区域时，先画该 cell 的包围盒占位（避免白屏）。

## 5. 悬停与拾取

```
mouseMove（无按键）
 -> SelectTool::hover(pos)
 -> 节流 50 ms
 -> Picker::pick(screenPos)
      CPU: camera->toWorld(pos) -> HitTester::hitTest(world, tol)
      GPU: renderIdBuffer -> 读命中像素的 id
 -> 若命中变化：
      -> document->setHover(selectionId)
      -> PropertyPanel 可显示「悬停」信息
      -> requestRepaint（高亮预览）
```

- 命中优先级：**面积小的在上**（同位置多层重叠时先命中更小图元），再按图层 `zOrder` 从高到低。
  规则只在 `HitTester` 实现一次。
- 命中结果必须包含**实例路径**，属性面板才能显示 `TOP/A/B#3` 这样的定位。

## 6. 选择与属性

```
左键单击 -> SelectTool -> Picker::pick -> ElementRef
 -> DocumentController::setSelection(ids, mode)   // Replace/Add/Toggle
 -> document->selection() 更新
 -> emit selectionChanged(ids)
 -> PropertyPanel 重建内容（层、类型、bbox、面积、文本、变换细节）
 -> requestRepaint（高亮）
```

- 框选：`HitTester::hitTest(rect)`；命中超过 1 万条时只返回前 N 条并提示「结果过多」。
- 「选中同 cell 的所有实例 / 同层所有图元」作为增强，接口预留 `SelectionFilter`。
- 选择集存 `core::ElementRef`（cell + slot 句柄），**不存快照指针**；元素被删除后自动剔除。

## 6.5 编辑一次选择集（V2 的核心时序）

```
用户拖动选中图形（MoveTool）
 -> mousePress：记录起点、快照"被移动元素"的当前几何 -> 生成 ghost 预览
 -> mouseMove ：SnapEngine 求吸附点（顶点 > 边 > 实例原点 > 网格）
                 -> EditOverlay 更新候选几何 -> requestRepaint（不碰 Layout）
 -> mouseRelease：delta 取整到网格
 -> EditController::apply(MoveRequest{refs, delta})
      -> layout.beginTransaction("Move")            // GUI 线程，同步
      -> 对每个 ref：replaceShape / setInstance
          失败 -> rollback + 错误提示（模型不变，预览消失）
      -> commit -> EditHistory.push(txn)
      -> SceneUpdater::apply(txn.dirtyCells())
           1) 重建脏 cell 的 CellGeometry
           2) 沿 parents 上溯 bbox
           3) 发布新 SceneGraph（复用未变条目）
      -> emit editCommitted(label) / sceneChanged()
      -> PropertyPanel 刷新；dirtyChanged(true)（若离开保存点）
```

**要点**

- 拖动期间**没有事务、没有模型修改**：所以 60 FPS 与 cell 大小无关，Esc 取消零成本。
- 一次手势 = 一个事务 = 一步撤销；多选批量修改也只产生一步。
- 提交是同步的（毫秒级）；只有「大 cell 重建」才切到后台（09 §5.2）。

---

## 6.6 撤销 / 重做

```
Cmd+Z
 -> EditController::undo()
      -> history.undo(layout)          // 逆序应用前像
      -> SceneUpdater::apply(dirty)    // 与编辑提交完全同一条路径
      -> emit editCommitted("Undo: Move") / dirtyChanged(history.isAtSavePoint() ? false : true)
```

- 撤销栈为空时命令置灰（`canUndo()` 驱动 `QAction::setEnabled`）。
- 撤销后选择集若指向已恢复的旧句柄，仍然有效（slot + generation 保证）；指向已删除元素则剔除。
- 历史截断（超内存）时提示一次，不打断操作。

## 6.7 保存 / 另存为

`Cmd+S` 的默认语义是**原地覆盖**（已确认必须能直接存档）；`Cmd+Shift+S` 才是另存为。
格式不支持写出、路径不可写或用户显式选择时，才降级/转为另存为。

```
Cmd+S
 -> DocumentController::save()
     -> 若 readOnly / 无路径 / 该格式无 writer -> 走 Save As 对话框
     -> 外部修改检测：比对 (mtime, size, inode) 与打开时记录的快照
          不一致 -> 冲突对话框：Overwrite / Save As / Reload / Cancel
     -> document->lockEditing()                  // 编辑入口置灰，避免存到半改状态
     -> TaskRunner::run("save", ...)  ---------- IO 线程 ----------
          -> writer.write(layout, tmpPath, options, progress)   // 只读 Layout 快照
          -> fsync(tmp) + 计数校验（cell 数 / 图元数 / bbox）
     <-- queued: onDone(Result<WriteStats>) ------ 主线程 ----------
     -> 成功：原文件复制为 <file>.bak（默认开启）
              -> rename(tmp -> target)                       // 原子替换
              -> 若 lypDirty：写 <file>.lyp；再写 <file>.eda.json（视图状态）
              -> history.markSaved()；标题栏去 *；unlockEditing()
     -> 取消：删除 tmp；保持 dirty
     -> 失败：错误对话框；原文件未动；保持 dirty，允许重试
```

- 临时文件放**同目录** `.tmp-<pid>-<rand>`（同一文件系统才能 `rename` 原子替换）。
- **保存顺序**：先几何、后图层属性/视图状态。几何失败 → 全盘回退；`.lyp` 写失败只告警
  （几何已落盘，不回滚，避免「以为没存上」再存一次）。
- **崩溃/断电恢复**：启动或打开文件时扫描 `<target>.tmp-*`，发现残留 → 提示「恢复上次未完成的保存」。
- **`.bak`** 默认每次保存前把原文件复制为 `<file>.bak`（设置可关），只保留一份不滚动，
  避免 `.bak.1/.bak.2` 无限增长。
- 保存期间 **拖动/绘制工具被禁用**；事务必须已提交（不允许存半个事务）。
- 大文件保存进度按「已写 cell 数 / 总 cell 数」估算（写入量比字节数更均匀）。
- **格式保持**：原地保存不改变格式与单位；打开 GDS 就写 GDS，打开 OASIS 就写 OASIS。
  用户要换格式只能另存为，并在对话框里提示「另存为新格式可能丢失格式特有属性」。

## 7. 图层操作

```
LayerPanel 勾选框
 -> LayerTableModel::setData(visible)
 -> DocumentController::setLayerVisible(key, bool)
 -> LayerStyleTable::setVisible()
 -> emit layersChanged()
 -> LayoutView::requestRepaint()
（不重建 SceneGraph）

LayerPanel 改颜色
 -> DocumentController::setLayerColor(key, color)
 -> 样式表更新 + renderer->invalidateLayer(key)   // 只重建该层顶点色/批次
 -> requestRepaint()

LayerPanel 拖动排序
 -> 重排 zOrder -> 重排 draw 列表（不重建顶点）

LayerPanel 改层号 / 批量迁移（V2）
 -> EditController::apply(LayerChangeRequest{refs, newLayer})
 -> 事务：逐元素 replaceShape + 必要时 AddLayer
 -> 增量重建受影响 cell -> 面板与层计数刷新
```

> 图层样式的显隐/颜色是**视图状态**（可撤销但不进文件）；层号/迁移是**数据修改**（进文件、走事务）。
> 两者必须分开实现，否则用户会误以为"改了颜色就改了文件"。

## 8. 切换顶层单元 / 单元树导航

```
CellTreePanel 双击某 cell
 -> DocumentController::setTopCell(cellId)
 -> TaskRunner 构建新 SceneGraph（同一 Layout，无需重新解析）
 -> 构建完成 -> 原子发布快照 -> emit sceneChanged -> zoomFit -> 面板更新
```

- 单元树中「引用节点」与「定义节点」要区分（同一 cell 可能出现在多处）。
- 树节点按需展开：`hasChildren` 依据引用关系动态判断，避免预展开百万实例。

## 9. 测量

```
MeasureTool::mousePress(点1) -> 吸附(snap)到最近顶点/边/网格
MeasureTool::mouseMove        -> 实时预览（叠加层，不入文档）
MeasureTool::mousePress(点2)  -> DocumentController::addMeasure(p1, p2)
 -> EditHistory.push(AddMeasureCmd)
 -> emit measuresChanged -> MeasurePanel 增行 + requestRepaint
Esc -> 取消未完成的测量（不入栈）
```

吸附优先级：顶点（≤ 8 px）> 边（≤ 6 px）> 网格（≤ 6 px）> 自由坐标；
吸附半径按 DPR 缩放。测量值同时显示 µm 与 DBU。

## 10. 导出图片

```
File > Export Image...
 -> ExportDialog（区域：当前视图 / 整个版图 / 指定 box；缩放；背景；是否含叠加层）
```

## 11. 关闭文档与退出

```
closeDocument
 -> 若 dirty -> 询问「Save / Discard / Cancel」（Cancel 直接返回）
 -> TaskRunner.cancelAllFor(document)
 -> 保存侧车：`.lyp`（图层属性，若 dirty）与 `.eda.json`（顶层/相机，若开启「记住视图」）
    // 即使几何未保存也写 .lyp（与 KLayout 一致）；设置里可关
 -> 清空 selection/measure -> emit documentClosed
 -> Document 析构 -> EditHistory -> Layout 释放

退出应用
 -> 遍历文档：逐个走 closeDocument 的 dirty 检查（取消则中止退出）
 -> 保存 geometry/state -> 反初始化 renderer（释放 GL 资源）-> 退出
```

## 12. 信号/槽清单（模块解耦的核心契约）

| 发送者 | 信号 | 订阅者 | 用途 |
|---|---|---|---|
| `DocumentController` | `documentOpened(Document*)` | MainWindow、所有面板 | 重建模型 |
| `DocumentController` | `documentClosed(Document*)` | 同上 | 清空 |
| `DocumentController` | `sceneChanged(SceneStats)` | 状态栏、诊断 | 统计刷新 |
| `DocumentController` | `layersChanged()` | LayerPanel、LayoutView | 刷新/重绘 |
| `DocumentController` | `selectionChanged(const SelectionSet&)` | PropertyPanel、LayoutView | 属性与高亮 |
| `DocumentController` | `cameraChanged(const Camera2D&)` | 状态栏、Minimap | 坐标/缩放显示 |
| `DocumentController` | `externalModificationDetected(path)` | MainWindow（冲突对话框） | 保存/重载前提示 |
| `CommandRouter` | `executed(const CommandResult&)` | 面板、状态栏、LayoutView、控制台 | 统一刷新（计数/高亮/脏标记/结果打印） |
| `CommandRouter` | `stateChanged()` | MainWindow（动作表） | 统一刷新菜单/快捷键/工具栏可用性 |
| `EditController`（内部） | `editCommitted(const EditResult&)` | `CommandRouter` | 命令层收尾后再转发 `executed` |
| `EditController` | `dirtyChanged(bool)` | MainWindow（标题栏 `*`）、关闭确认 | 保存状态 |
| `EditController` | `historyChanged()` | 编辑历史面板、撤销/重做 QAction | 可用性刷新 |
| `EditController` | `selectionPruned(size_t n)` | 状态栏 | 提示"已移除失效选择" |
| `TaskRunner` | `progress(name, done, total)` | 进度对话框 | 进度 |
| `TaskRunner` | `finished(name, Result)` | 发起者 | 结果回投 |
| `LayoutView` | `cursorMoved(worldPoint)` | 状态栏 | 坐标显示（节流） |
| `LayoutView` | `pickRequested(pos)` | DocumentController | 解耦 UI 与命中逻辑 |

订阅纪律：**面板之间不互相 connect**，跨面板协作一律经过 `DocumentController`。

## 14. 一致性约束（避免「同一动作不同路径表现不一致」）

1. 会改变可见结果的操作 → 必须发一条**命令**（`CommandRouter::invoke`），由命令层分派到
   `DocumentController`（视图类）或 `EditController`（数据类）→ 必须发对应信号 →
   必须 `requestRepaint()`。
2. 可能 > 50 ms 的操作 → 必须走 `TaskRunner`，且带取消。
3. 对 `Document` 状态的读写都在主线程；后台线程只处理**拷贝进来的不可变输入**，
   结果通过 queued 信号回投。
4. 面板只读快照，不缓存「可能过期的模型指针」；用 `Document*` + 信号驱动刷新。
5. 同一状态有两个入口（菜单/快捷键）时，都调用同一个命令方法，不各自实现。
6. **数据修改必须走事务**：不允许出现「工具里直接 `layout.replaceShape`」这种旁路，
   否则撤销与脏 cell 追踪会失配（CI 里可用 `Layout` 写接口的访问控制 + code review 保证）。
7. **保存只有一个入口**：`file.save` / `file.saveAs` 命令（内部落到
   `DocumentController::save()/saveAs()`）；任何面板不得自己写文件。
   保存前必须检查外部修改（`wasExternallyModified()`），写盘必须走同目录临时文件 + `rename` 原子替换。
8. **界面操作只发命令**：菜单/快捷键/工具栏/面板/视口工具一律
   `CommandRouter::invoke(命令ID, 参数)`，不直接调 `DocumentController`/`EditController`；
   工具的可预览手势（拖动/绘制）在**提交时**才发一条命令（11 §5）。
   新增功能先加命令 ID 再接入 UI，避免出现「只有鼠标能触达」的隐藏路径。
