# 05 渲染与性能设计

> 目标：在 10⁷ 图元规模下保持交互流畅，且坐标不错位、线宽不发虚、缩放到极限不崩。
> 结论先行：**层次树 + 按 cell 缓存几何 + LOD + 相机相对坐标**，四个手段缺一不可。

---

## 1. Camera2D（唯一的世界↔屏幕换算点）

```
struct Camera2D {
    double centerX, centerY;     // 世界坐标中心（µm）
    double pxPerMicron;          // 缩放（已含 devicePixelRatio）
    QSize  viewportPx;           // 物理像素尺寸（= 逻辑尺寸 × dpr）
    bool   flipY = true;         // 版图 y 向上，屏幕 y 向下
};
```

```
screen = (world - center) * pxPerMicron * (flipY ? -1 : 1) + viewport/2
world  = (screen - viewport/2) / pxPerMicron * (flipY ? -1 : 1) + center
```

| 操作 | 公式 / 规则 |
|---|---|
| `zoomFit(box, marginRatio)` | `pxPerMicron = min(w/boxW, h/boxH) * (1-margin)`；`center = box.center`；空 box 用默认视图 |
| `zoomAt(screenPt, factor)` | 先求该屏幕点对应的世界点 `w0`；改缩放；再平移使 `w0` 仍映射到同一屏幕点 |
| `panByPixelDelta(dx, dy)` | `center -= (dx, dy) / pxPerMicron`（注意 flipY） |
| 缩放范围 | `pxPerMicron ∈ [1e-9, 1e7]`（1 nm ≈ 1e-3 µm，再放大无意义） |
| 网格步长 | 目标 40–120 px 一格，步长取 `1/2/5 × 10^k` µm；次网格 1/5 或 1/10；标尺文字随之切单位 |
| 帧内不变 | 一帧内 `pxPerMicron` 与 `viewport` 必须一致，避免抖动 |

**相机相对坐标（关键精度措施）**

世界坐标可能到 1e6 µm，而 `float32` 只有 24 位尾数（1e6 处分辨率约 0.06），直接用 `float`
顶点会抖动。做法：

1. 顶点以 **cell 局部坐标**存 `float`（相对该 cell 原点，量级小）；
2. 每个实例的变换在 CPU 用 `double` 合成出 `modelView`（以 `float` 传给 shader）；
3. 若某 cell 自身跨度也很大（> 1e4 µm），按 2048 µm 的瓦片切分，顶点相对瓦片原点。

## 2. 顶点格式与批处理

### 2.1 顶点

```
struct LayoutVertex {          // 16 B
    float x, y;                // 局部坐标（µm）
    uint32_t rgba;             // 层颜色（含 alpha），避免每层换 uniform
    uint32_t elementSlot;      // 拾取用：slot 低 32 位（ID buffer 模式）
};
```

- 三角形用索引缓冲（`uint32`），矩形/多边形统一走三角化。
- 一层的几何连续存放 → 一次 `glDrawElements` 覆盖该层，减少 draw call。
- `LayerBatch` 另存 `elementKeys` 偏移表：`elementSlot → ElementKey`（含 generation），
  拾取结果据此还原稳定句柄（编辑后仍有效）。

### 2.2 批次（Batch）

```
CellGeometry
 └── layers: vector<LayerBatch>
               LayerBatch { LayerKey key; vector<LayoutVertex> v; vector<uint32_t> idx;
                            Box localBox; uint32_t elementIdBase; }
```

- `LayerBatch` 是**上传 GPU 的最小单位**，也是 LOD 决策单位（可整层跳过）。
- 颜色改变只需重写 `rgba`（MVP 用顶点色；进阶可改 uniform + 顶点存层索引）。

### 2.3 Shader 与填充/描边

```
vertex:   gl_Position = u_proj * u_model * vec4(a_pos, 0, 1);   v_color = a_color;
fragment: color = v_color;   // 混合模式：SRC_ALPHA, ONE_MINUS_SRC_ALPHA
```

| 方案 | 优点 | 缺点 | 选择 |
|---|---|---|---|
| 三角化填充 + 单独描边批次 | 简单可控 | 顶点翻倍 | ✅ MVP |
| 模板缓冲奇偶填充（原样画多边形） | 无三角化成本、支持自交 | 2 遍 + 清模板 | V1 可选 |
| 几何着色器生成描边 | GPU 端省 CPU | macOS GL 4.1 难调试 | ❌ |

- 极细图元（屏幕面积 < 2 px²）直接画 1–2 px 矩形，避免三角形退化。
- 半透明：默认填充 alpha ≈ 0.85 + 不透明描边；层序已知，按层从底到顶画，不需要全局排序。

## 3. 场景遍历与绘制流程

```
renderLayout(camera):
  visibleBox = camera.worldBox()
  walk(cellId = scene.topCell, modelMatrix = I, lod):
      geometry = scene.cells[cellId]                       // shared_ptr，命中缓存
      for batch in geometry.layers:                        // 先画本 cell 的形状
          if lod.decide(cellBox, batch) == Cull: continue
          drawBatch(batch, modelMatrix)                    // 一次 draw call 一层
      for inst in geometry.instances:                      // 再递归子 cell
          childBox = modelMatrix * inst * targetBox
          switch (lod.decide(childBox, inst)):
            case Cull:    continue
            case Box:     drawBox(childBox, layerColor)     // 极远/极小的实例
            case Recurse: walk(inst.target, modelMatrix * inst.transform, lod)
```

**要点**：几何与实例都在 `CellGeometry` 里，所以「改一个 cell」= 换一个 `shared_ptr`，
父 cell 与兄弟 cell 的顶点缓冲完全不动（编辑后增量刷新的基础，见 09 §5）。

`LodPolicy::decide` 默认判据（可配置）：

| 判据 | 阈值 | 决策 |
|---|---|---|
| 节点屏幕包围盒 < 1.5 px | — | `Cull` |
| 节点包围盒 < 8 px 且有子节点 | — | `Box`（实心小方块） |
| 节点包围盒 < 32 px 且该 cell 图元数 > 500 | — | `Box` 或简化几何 |
| 单帧已画图元数 > 预算（默认 1.5×10⁶） | — | 剩余节点降级为 `Box` |
| 其他 | — | `Geometry` + `Recurse` |

- **层叠顺序**：若按层次顺序绘制出现「上层被下层覆盖」，改为「按层分桶」：
  遍历时收集 `(cellId, matrix, layer)`，按 `(layerZ, depth)` 排序后分批绘制（MVP 先按层次顺序）。
- 每帧实例数上限（默认 20 万）防止病态数据卡死；超限提示「已简化显示」。

## 4. 层次树 vs 全拍平（为什么这样选）

| 方案 | 内存 | 每帧 CPU | 选择/属性 | 实现复杂度 |
|---|---|---|---|---|
| 全拍平（AREF 全部展开） | 可能 10–100× 爆炸 | 低 | 需记录来源路径 | 低 |
| **层次树 + 按 cell 缓存**（本设计） | 与文件同量级 | 低（节点数远小于图元数） | 天然有路径 | 中 |
| 瓦片金字塔（预烘焙） | 中等（可落盘） | 最低 | 需反查 | 高（V2 可选） |

**结论**：以层次树为主；对「一个 cell 被 10⁵ 次引用且变换各异」的极端情况，用实例化绘制
控制 draw call（内存不增）。

### 4.1 实例化绘制（Instancing）

- 同一 `cellId` 在同帧出现多次 → `glDrawElementsInstanced`，每实例一个压缩矩阵（3×vec4）。
- 限制：`instanceCount × cellVertices` 不得超过顶点预算，否则退回逐个绘制或 LOD 成盒子。
- 遍历时按 `cellId` 分组（每帧复用 `unordered_map`，避免反复分配）。

## 5. 拾取（Hit Testing）

### 5.1 CPU 路径（MVP）

```
pick(screenPos):
  world = camera.toWorld(screenPos)
  tol   = tolerancePx / camera.pxPerMicron        // 像素容差转世界容差
  递归遍历可见节点（包围盒外扩 tol 后剪枝）:
      局部点 = inverse(node.matrix) * world
      在 CellGeometry 中按层、按包围盒查找候选图元
      取「面积最小 + 层最上」的命中
```

- `CellGeometry` 内部按层维护**均匀网格**（cell 局部坐标，网格边长 ≈ cell 尺寸 / 32），
  每格存图元索引（4 B/引用）。
- 容差：点选 3 px、边 5 px、顶点吸附 8 px（可配置）。
- 线（Path）的距离计算在局部坐标系做，容差需除以 `mag`（缩放后等效容差变化）。

### 5.2 GPU ID Buffer（V1）

```
离屏 FBO(RGBA8 / R32UI) -> 每个图元用唯一 id 着色（无混合）
鼠标位置 -> glReadPixels(1x1) -> id -> 反查 ElementRef
```

- 频率受控（鼠标停 50 ms 后或点击时），避免每帧同步读像素拖慢管线。
- id 编码：`(instanceSlot << 24) | elementSlot`；每帧重建 `instanceSlot → 实例路径` 表，
  再用 `LayerBatch::elementKeys` 把 `elementSlot` 还原成 `ElementKey`。
- 优点：与几何复杂度无关；代价：一张屏幕大小 RT + id 映射维护。

### 5.3 两条路径的一致性

必须返回相同的 `ElementRef` 与相同的「最上 / 最小」规则；
用同一组用例（重叠图元、跨层、缩放后细线）验证两条路径结果一致。

## 6. 内存与显存预算

| 项目 | 估算 | 控制手段 |
|---|---|---|
| 模型（`Layout`） | ≈ 40–80 B/图元 | 紧凑结构 + 字符串池 + AREF 不展开 |
| 场景节点 | ≈ 64 B/实例节点 | 上限 5×10⁶ ≈ 320 MB（超限折叠） |
| CPU 顶点（`CellGeometry`） | 16 B/顶点，平均 4–6 顶点/图元 | 按需构建（LRU）+ 低 LOD 用盒子 |
| GPU 顶点缓存 | 默认上限 1 GB（可配 256 MB–2 GB） | LRU 淘汰；超限降 LOD |
| 拾取网格 | 4 B/图元引用 | 只为需要拾取的 cell 建 |
| ID buffer | W×H×4 B ≈ 15 MB（4K） | 单张复用 |
| **撤销栈（编辑态）** | ≤ 512 MB（可配） | 超出从栈底截断；大操作提示 |
| **选择集** | 16 B/元素 | 1e5 元素 ≈ 1.6 MB |

**显存 LRU**：键为 `(cellId, lodLevel)`；淘汰时删 VBO/VAO；CPU 侧几何保留以便快速重传
（内存紧张时也可丢弃，重新生成代价约十几毫秒）。

**规模假设**（README §1）：单文件 ≤ 1 GB、图元 ≤ 2×10⁷、AREF 展开实例 ≤ 10⁵、层次深度 ≤ 64。
据此实例节点表按 ≤ 10⁶ 预留即可，**不再做** tile 化/流式场景与百万实例折叠；
超出假设时降级为「折叠 + 状态栏提示」，保证不卡死、不 OOM，但不承诺交互流畅。

## 7. 帧预算与卡顿排查

| 阶段 | 预算（60 FPS，16.6 ms 总） | 观测点 |
|---|---|---|
| 场景遍历 + LOD 决策 | 2 ms | `FrameStats::traversalMs` |
| 顶点上传（脏批次） | 3 ms | `uploadMs`、`uploadedBytes` |
| draw call 提交 | 2 ms | `drawCalls`、`instances` |
| QPainter 叠加层 | 3 ms | `overlayMs` |
| GPU | 剩余 | `QOpenGLTimerQuery`（可选） |

**常见卡顿与对策**

| 现象 | 原因 | 对策 |
|---|---|---|
| 首次进入某区域卡一下 | 大量顶点上传 | 分批上传（每帧上限 8 MB）+ 先画盒子 |
| 缩放时闪烁 | LOD 阈值抖动 | 加滞回（进入/退出用不同阈值） |
| 缩到全图很慢 | 画了全部细节 | 强制盒子模式 + 层合并 |
| 鼠标移动就掉帧 | 悬停拾取过频 | 50 ms 节流 + 必要时才重建 ID buffer |
| 文本很卡 | 每帧重建文本 | 只在相机变化后重建并缓存 QPixmap |

## 8. 软件渲染后端（SwRenderer）

用途：坐标/层次正确性验证、离屏导出、无 GL 环境兜底。

- `QPainter` + `QPainterPath`：多边形 fill + 描边；路径用 cosmetic pen（恒定 1 px）。
- 性能：适合 ≤ 5×10⁴ 可见图元；超出则按层画包围盒/抽样。
- 与 GL 后端共享 `Camera2D`、`LodPolicy`、`LayerStyleTable`，保证两种后端「看起来一致」。
- 导出：`QPainter::Antialiasing`，`QImage::Format_ARGB32_Premultiplied`。

## 9. 叠加层（网格、标尺、测量、文本）

| 元素 | 实现 | 注意 |
|---|---|---|
| 网格 | `QPainter` 按相机步长画线（或 GL） | 主/次网格不同透明度；缩放时淡入淡出 |
| 标尺/坐标轴 | 视口边缘刻度 + 单位文字 | 单位随缩放切 nm/µm/mm |
| 测量 | 线段 + 端点标记 + 文本（dX/dY/长度/角度/面积） | 文本带背景框保证可读 |
| 书签 | 小旗标 + 名称 | 双击跳转 |
| 十字光标 | 1 px 十字线 + 坐标提示 | 仅视口内、开启时绘制 |
| **编辑预览（ghost）** | 候选几何（半透明填充 + 虚线描边）+ 吸附点 + 尺寸提示 | 与真实几何同一坐标系；不写模型 |
| 单元名/文本 | 见 02 第 4.4 节 | 数量上限 + 屏幕尺寸阈值 |

绘制顺序：GL 版图 → `QPainter` 一次 `begin/end` 画完叠加层，减少状态切换。
编辑预览必须画在**选择高亮之上、光标之下**，避免遮挡数值提示。

## 10. 视觉与交互一致性

1. **线宽**：屏幕像素恒定（1 px）；放到极大时可选「物理线宽」模式。
2. **颜色**：内建 `layer → color` 稳定哈希；深色/浅色两套默认；alpha 一致。
3. **顺序**：层按 `zOrder`；同层内多边形在路径下，文本在最上。
4. **高亮**：选中 = 加亮 + 白色描边；悬停 = 加亮不描边，两者不混淆。
5. **空状态**：无文档时显示网格 + 提示（拖入文件 / Cmd+O）。
6. **错误可视化**：缺失 cell → 品红虚线框；循环引用 → 红色虚线框 + 名称。

## 12. 增量快照与编辑响应（V2）

编辑把「一次全量构建」变成「持续的小更新」，渲染侧要配合三件事：

### 12.1 快照发布是 O(脏 cell)

```
newScene = oldScene.cloneShallow()            // 只拷 map（cellId → shared_ptr），不拷几何
for cell in dirtyCells: newScene.cells[cell] = buildCellGeometry(layout.cell(cell))
atomic_store(currentSnapshot, newScene)       // 渲染线程下一次 paintGL 取到新指针
```

- 未变的 `CellGeometry` 被新旧快照共享 → **GPU 缓存不需要失效**（缓存键里带 `geometry.get()` 或
  `revision` 即可）。
- 旧快照在下一帧结束后自然释放，不需要显式同步。

### 12.2 GPU 侧：只重传脏几何

| 变化 | GPU 动作 |
|---|---|
| cell 形状变化 | 该 cell 的 VBO 标记为脏 → 下一帧重传（分帧上限 8 MB） |
| cell 实例列表变化 | 只影响遍历，不重传顶点 |
| 图层颜色变化 | 重写该层批次的 `rgba` 或改 uniform（不重建顶点） |
| 相机变化 | 只更新 uniform |

**缓存键**：`(geometryPtr, lodLevel)`；用指针做键的前提是几何不可变（与 D4 一致）。
若实现里改用 `revision`，则 revision 必须全局单调（cell 内 revision 会重号）。

### 12.3 交互期：预览不等待几何

- 拖动/绘制期间按 §9 的「编辑预览」直接画候选几何，**不等** `CellGeometry` 重建。
- 松手提交后：若重建 ≤ 8 ms → 同步完成再刷新（用户看不到中间态）；
  否则先保持旧几何 + 预览，重建完成后再替换（避免闪一下旧数据）。
- 大 cell（> 5×10⁵ 图元）重建期间，状态栏显示 "Updating geometry…"，并允许继续平移缩放。

### 12.4 编辑相关的性能验收

| 场景 | 指标 |
|---|---|
| 拖动 1000 个多边形（跨 1 个 cell） | ≥ 60 FPS（全程只画预览） |
| 松手提交（cell ≤ 2×10⁴ 图元） | 提交到画面更新 ≤ 100 ms |
| 松手提交（cell = 2×10⁵ 图元） | ≤ 250 ms，期间 UI 可响应 |
| 撤销/重做单步 | ≤ 50 ms |
| 连续 200 次编辑 | RSS 增长 ≤ 撤销栈上限，且无泄漏 |
