# 01 总体架构

## 1. 分层与依赖规则

| 层 | 命名空间 | 依赖 | 是否依赖 Qt | 职责 |
|---|---|---|---|---|
| 内核 | `eda::core` | 仅 C++ 标准库 | ❌ 不依赖 | 几何、变换、单位、数据模型（可变）、事务、错误码 |
| 格式 | `eda::io` | core, zlib | 仅 `QString`/`QFile` 边界（可用 `std::filesystem` 替代） | 读写 GDS/OASIS，产出/消费 `Layout` |
| 场景 | `eda::scene` | core, io, QtCore（并发/信号） | QtCore | 层次展开、LOD、空间索引、命中测试、场景构建任务 |
| 编辑 | `eda::editing` | core, io, Clipper2 | ❌ 不依赖 | 事务与撤销、编辑操作、吸附、编辑检查与布尔运算（V2） |
| 命令 | `eda::command` | core, editing | ❌ 不依赖 | 命令表、执行管线、参数编解码、命令日志（见 11） |
| 渲染 | `eda::render` | core, scene, OpenGL | QtGui/OpenGLWidgets | 相机、顶点批处理、绘制、拾取、图层样式、叠加层 |
| 表现 | `eda::ui` | core, scene, render, editing, QtWidgets | QtWidgets | 主窗口、视口控件、Dock 面板、Model/Delegate、工具状态机 |
| 应用 | `eda::app` | 以上所有 + QtConcurrent | Qt | 生命周期、文档、编辑控制器、设置、任务调度、日志 |
| 插件 | `eda::plugin` | core 接口 + QtPlugin | Qt | 第三方扩展宿主 |

**硬性规则**

1. `core` 项目中禁止出现 `#include <Q...>`；CI 里加一条 grep 检查。
2. `scene` 不得 include `render`/`ui`；`render` 不得 include `ui`；`editing` 不得 include `scene`。
3. UI 只能通过 `command::CommandBus`（经 `app::CommandRouter`）修改状态，**不得直接改 `Layout`**
   或调用 `EditController::apply`（所有写入必须走 `Transaction`，否则撤销失效、脏 cell 追踪失效）。
   命令之外无写入，见 [11-命令总线与命令协议](11-命令总线与命令协议.md)。
4. 跨模块只传 `core` 中定义的值类型 / 接口类型；不暴露 STL 容器到公开 ABI（版本敏感时可改用 span）。
5. 所有公共头文件用 `#pragma once`，包含顺序：本文件 → core → 第三方 → Qt → 标准库（由 clang-format 排序）。

**为什么把「场景」独立成层？**
`Layout`（文件里的）与 `SceneGraph`（画布上的）不是一回事：同一个 Layout 可以有不同的
顶层单元、不同的图层过滤、不同的 LOD；而 SceneGraph 还承担缓存、索引、并发构建。
把两者分开，切换顶层单元/过滤条件时只需重建 SceneGraph，不重新解析文件；
编辑时只重建受影响 cell 的 `CellGeometry`（见 09 §5）。

**为什么把「编辑」独立成层？**
编辑的复杂度在**语义**（事务、句柄失效、层次环路、吸附、合法性检查），不在 UI。
把它放在 `core` 之上、`ui` 之下，意味着：可以用无 GUI 的测试直接验证「移动 1000 个图形
后撤销能完全还原」；UI 只负责把鼠标事件翻译成命令（11 §5.4）。

## 2. 运行时对象视图

```
QApplication
 └── app::Application                    （单例式，持有全局服务）
      ├── app::Settings                  （QSettings + 默认值）
      ├── app::TaskRunner                （QThreadPool，进度/取消）
      ├── plugin::PluginManager
      ├── app::CommandRouter             （命令入口：UI/控制台/脚本/socket → CommandBus）
      │    └── command::CommandBus       （无 Qt：命令表 + 校验 + 事务 + 日志，见 11）
      └── app::DocumentController        （1 个，跨窗口）
           └── app::Document*            （0..N，每个打开的版图一个）
                ├── core::Layout         （**可变**数据源：cells / layers / units）
                ├── core::EditHistory    （事务栈：undo/redo，见 09）
                ├── scene::SceneGraph    （渲染快照，增量替换）
                ├── render::LayerStyleTable
                ├── scene::SelectionSet   （元素稳定句柄集合）
                ├── overlay::Ruler/Bookmark 集合
                ├── bool readOnly / dirty / 保存点标记
                └── FileMeta             （路径、格式、units、打开耗时、统计）

ui::MainWindow                          （1 个）
 ├── ui::LayoutView (QOpenGLWidget)     （主视口，持有 Camera2D 与 IRenderer 实例）
 ├── ui::CellTreePanel  (QDockWidget)
 ├── ui::LayerPanel     (QDockWidget)
 ├── ui::PropertyPanel  (QDockWidget)   （V2 起可编辑字段）
 ├── ui::EditHistoryPanel（V2）
 ├── ui::MeasurementPanel / MessagePanel
 └── QStatusBar 自定义组件（坐标/缩放/统计/FPS/编辑模式）
```

**关键点**

- `Layout` 是**唯一可写数据源**；它只被 GUI 线程修改，且只能经由「一条命令 → 一个 `Transaction`」
  （V1 只读时也一样，读路径不感知差异）。
- `SceneGraph` 是**不可变快照**：编辑提交后由 `SceneUpdater` 重建脏 cell 的 `CellGeometry`
  并发布新快照，渲染线程永远只读。
- `Document` 是状态的唯一入口；「当前顶层单元、过滤、选择、相机、编辑模式」都属于 Document 级
  （相机也可以视口级，见 05 文档，MVP 采用 Document 级单视口）。
- `LayoutView` 不持有数据，只持有 `Document*` 与 `Camera2D`；`paintGL` 时向 Document 取快照。

## 3. 线程模型

| 线程 | 数量 | 做什么 | 严禁做什么 |
|---|---|---|---|
| GUI 主线程 | 1 | 事件分发、Qt Widgets、GL 上下文（`QOpenGLWidget` 的绘制与 VBO 上传）、**所有 `Layout` 变更**、场景快照切换 | 解析文件、构建大型场景、同步 IO |
| IO 线程 | 1（按任务） | `FormatReader` 读取并构建 `Layout`；`FormatWriter` 写出 | 触碰任何 QWidget / GL |
| 场景构建池 | `min(硬件线程, 4)` | 每个 cell 的几何归一化、包围盒、层内分组、索引构建、三角化（**只读 Layout**） | 修改 Layout；上传 GL |
| 导出线程 | 1 | 离屏渲染（软件后端）或数据导出 | 修改 Document 状态 |

**数据流约束（避免数据竞争）**

- `Layout` 在 IO 线程构建完成后**整体移交**（`unique_ptr` 移动）给 GUI 线程。
- **写入只发生在 GUI 线程**：`Transaction::commit` 之后，Layout 处于「静止」状态；
  场景构建池与写出线程只在**静止窗口**内读取。为把这点变成编译期/运行期约束，采用三条规则：
  1. 编辑提交是同步的（毫秒级），提交期间不派发任何异步构建；
  2. 场景构建任务读取的是 `CellSnapshot`（`const Cell&` 的只读视图 + `revision` 版本号），
     构建结束后校验 version，不一致则丢弃重做（乐观并发）；
  3. 保存（写文件）期间调用 `Document::lockEditing()`，UI 置灰编辑入口，避免读到半改状态。
- `SceneGraph` 在构建池内构建，完成后以 `shared_ptr<const SceneGraph>` 原子发布；
  旧快照由最后一个持有者释放（引用计数，无需锁）。
- `LayerStyleTable` 只由 GUI 线程修改；渲染时取 const 引用（同线程，天然安全）。
- 进度/取消：`TaskRunner` 提供 `std::atomic_bool` 取消标志 + `QMetaObject::invokeMethod`
  （QueuedConnection）回投结果；解析器每 N 条记录检查一次取消。

**为什么不让编辑在后台线程跑？**

- 事务 + 撤销栈 + 选择集 + 场景脏标记天然是「单线程状态机」，多线程化收益小（单次编辑毫秒级），
  风险大（锁序、死锁、撤销与构建交错）。
- 真正需要后台的是**大 cell（> 2×10⁵ 图元）的几何重建**与**保存**，这两者都在
  「Layout 静止窗口」内做，不需要与写操作并发。
- 若将来确实需要后台编辑（例如批量脚本改动百万图形），走 `TaskRunner` + 独占锁 +
  单一事务，仍然不并发。

**GL 上下文的坑（提前写进设计，避免返工）**

- `QOpenGLWidget` 的上下文只在 `initializeGL/paintGL/resizeGL` 以及显式
  `makeCurrent()` 区间内有效；`QOpenGLWidget` 必须在 GUI 线程创建与绘制。
- 因此所有 GPU 资源（VAO/VBO/纹理）只能在帧开始时「上传脏数据」，场景构建线程只准备
  **CPU 端顶点数组**。接口上体现为 `IRenderer::sync(const SceneSnapshot&)` → `render(...)`。
- `QOpenGLWidget` 默认使用 FBO + 合成，HiDPI 下要按 `devicePixelRatio()` 设置视口。

## 4. 所有权与生命周期

| 对象 | 所有权 | 生命周期 |
|---|---|---|
| `Layout` | `Document`（`std::unique_ptr`） | 打开 → 关闭文档 |
| `EditHistory` | `Document`（值成员） | 随文档；可设置上限并截断 |
| `SceneGraph` | `shared_ptr<const>`，Document 持有 current，`LayoutView` 渲染时临时持有 | 每次发布替换（复用未变 `CellGeometry`） |
| `CellGeometry` | `SceneGraph` 内（`shared_ptr<const>`） | 随快照；被多个快照共享 |
| GPU 资源 | `IRenderer` 内的 LRU 缓存 | 显存预算触发淘汰；上下文销毁时清空 |
| `QOpenGLWidget` | Qt 父子关系 | 主窗口 |
| 插件 | `PluginManager`（QPluginLoader） | 应用退出 |

**打开/关闭顺序**

1. 打开：选中文件 → 识别格式 → 弹进度 → IO 线程解析 → 得到 `Layout`
   → 选顶层单元（GDS 用第一个 STRNAME；OASIS 用 CELL 顺序第一个，或用户指定）
   → 构建首版 `SceneGraph`（可先粗后细）→ 适配视图 → 更新面板。
2. 关闭：若有未保存修改 → 询问「保存 / 丢弃 / 取消」→ 取消未完成任务 → 清空选择/标尺
   → 释放 `SceneGraph` → 释放 `EditHistory` → 释放 `Layout` → 通知所有面板重置
   → 渲染器释放 GPU 缓存。

## 5. 错误处理与可观测性

**错误统一为值类型**（不跨模块抛异常）：

```c++
enum class ErrorCode { Ok, FileNotFound, PermissionDenied, UnknownFormat, UnsupportedVersion,
                       CorruptRecord, TruncatedFile, TooLarge, OutOfMemory, Cancelled,
                       WriteFailed, ReadOnlyDocument, InvalidEdit, CycleDetected, Internal };
struct Error { ErrorCode code; int64_t offset; std::string message; std::string context; };

template <class T> using Result = std::expected<T, Error>;   // C++23 或自研简化版
```

- 解析器内部可以用异常实现「快速中止」，但**在 `FormatReader::read()` 边界捕获**并转成
  `Result`，保证上层只需要处理值。
- 每条错误都带**文件偏移 + 记录名 + cell 名**，方便定位损坏的 GDS；这是自研解析器相对
  第三方库的主要收益之一。
- 容错策略：局部损坏时（未知记录、不支持的 OASIS 特性）默认「记录并跳过」，
  状态栏显示 warning 计数，用户可在「消息面板」查看；严格模式由设置项控制。

**日志**：`QLoggingCategory` 分类 `eda.io.gds` / `eda.io.oasis` / `eda.scene` / `eda.render` /
`eda.ui`；默认只开 Info 以上，设置里可开 debug，并用 `QT_MESSAGE_PATTERN` 输出线程号。

**性能观测**：内建 `FrameStats`（CPU 构建耗时、draw call 数、可见图元数、VBO 上传字节、
显存占用、FPS），在状态栏与「诊断」对话框中显示；配合 `QElapsedTimer` 打点，
是否开启由设置控制（默认关闭以避免影响性能）。

## 6. 配置、状态与文件侧车

| 数据 | 存放位置 | 说明 |
|---|---|---|
| 用户偏好（主题、默认 LOD、线程数、字体） | `QSettings`（macOS `~/Library/Preferences`、Linux `~/.config`） | 跨文档共享 |
| 最近文件（最多 20） | `QSettings` | 含完整路径 + 打开时间 |
| 窗口布局（dock 位置、列宽） | `QSettings` 的 `geometry/state` | `saveGeometry/saveState` |
| 每文件的图层属性（名字/颜色/填充/图案/显隐/顺序/组） | **`<file>.lyp`（KLayout 兼容 XML，权威格式）** | 直接复用工艺厂给的 `.lyp`；保存文档时同步重写 |
| 每文件的视图状态（顶层单元、相机、标尺、书签） | 侧车 `<file>.eda.json` | 与 `.lyp` 共存，互不覆盖 |
| 撤销历史 | 内存（可选溢出到临时文件） | 上限可配（默认 512 MB / 200 步），见 09 §3 |

**界面语言**：仅英文。所有文案写英文常量，`tr()` 可保留但**不建 `.ts`、不做 `QTranslator`**；
刻意避免中英混排带来的排版/缩写问题（KLayout 用户也习惯英文界面）。

样式优先级：**`.lyp` > 用户默认图层模板 > 内建哈希配色**（layer,datatype 稳定映射，
同一层在所有文件里颜色一致）。`.eda.json` 只管视图，不参与配色。

- **`.lyp` 是权威**：读入时保留未知 XML 元素与属性（工艺厂文件里常有自定义字段），
  写出时原样带回，避免「保存一次就把厂里的层定义洗掉」。
- 修改图层属性**不进 `EditHistory`**（与 KLayout 一致：图层可见性/颜色属于视图状态，
  不进撤销栈）；只置 `lypDirty`，保存时一并写盘。
- 文件旁边没有 `.lyp` 且用户没改过图层属性时，**不凭空创建** `.lyp`（避免污染目录）；
  用户显式「Save Layer Properties」才生成。

## 7. 平台与 HiDPI

**交付平台只有两个**：macOS 13+（Apple Silicon 为主，兼顾 x86_64）与 Linux x86_64
（glibc ≥ 2.31、桌面 GL 4.1+）。**不交付 Windows**：没有 MSVC/windeployqt 分支，
也不承诺跨平台二进制插件兼容。

- macOS：`QOpenGLWidget` 可用（GL 4.1 Core），但已被 Apple 弃用 → V2 计划切换 `QRhiWidget`（Metal）。
  架构上通过 `IRenderer` 隔离，替换后端不影响上层。
- Linux：系统 Mesa（GL 4.1+）即可跑；Wayland 与 X11 都要能启动（Qt 6 默认 Wayland，
  必要时提供 `QT_QPA_PLATFORM=xcb` 作为兜底）。无 GPU/远程桌面时降级到 `SwRenderer`。
- HiDPI：所有像素尺寸换算统一经过 `Camera2D::pixelsPerMicron`，而它已包含 `devicePixelRatio`；
  线宽/点大小在 shader 或 QPen 里按 `dpr` 缩放；测试要覆盖 1x/2x，Linux 还要覆盖分数缩放（1.25/1.5）。
- 快捷键：用 `QKeySequence::StandardKey`，避免硬编码 `Ctrl`（macOS 为 `Cmd`）。
- 文件路径统一用 `QString`/`std::filesystem::path`，不用 `char*` 拼接；
  大小写敏感性差异（macOS 默认不敏感、Linux 敏感）在 cell 名查找与侧车文件匹配上都要考虑。
- 打包：macOS `.app` + `macdeployqt`（后续 codesign/notarize）；Linux `linuxdeploy` →
  AppImage（可选 deb + 源码构建说明）。两者都要求「干净机器可运行」，不依赖开发机的 Qt。

## 9. 非功能约束（设计时必须内建）

1. **可取消**：所有长任务都有取消点，取消后资源正确释放（RAII，不用 `new` 裸指针）。
2. **可回归**：渲染结果可截图对比；解析结果可序列化为稳定文本（dump 工具）做 diff。
3. **可诊断**：坏文件不崩溃、不静默；错误带偏移；有 `--dump` CLI 模式（无 GUI 也能跑解析）。
4. **内存可预估**：每个图元的目标开销（越界即报警）见 05 文档的内存预算表。
5. **UI 不阻塞**：任何 > 50 ms 的操作都要进 `TaskRunner`；进度对话框 300 ms 延迟出现（避免闪烁）。
6. **可访问性/可用性**：全功能键盘可达（缩放、图层开关、选择），颜色不单独承载信息
   （图层还有名字/序号/图案）。
7. **编辑可逆**：任何修改都必须可撤销；撤销后内存/几何/选择恢复原状（测试用「编辑 100 步后
   全撤销 → 与原始 dump 逐字节一致」验证）。
8. **保存不破坏原文件**：默认 `Cmd+S` 就是**原地覆盖**——写同目录临时文件 → `fsync` →
   原子 `rename` → 保留一份 `.bak`；写前校验外部是否被改过，写后校验 cell 数/图元数
   （见 09 §7）。格式不支持写出时才强制另存。

## 10. 参考实现与验证基准

- **KLayout**：坐标系、SREF/AREF 摆放语义、图层渲染顺序的事实标准；用它导出的截图做黄金对比。
- **gdstk / gdspy**：用于生成测试用 GDS（各种畸形/边界情况），便于 CI 里程序化产出样例。
- **GDSII Stream Format Manual**（Calma）：记录表与 real64 编码的权威来源。
- **SEMI P39（OASIS）**：varint、modal 变量、REPETITION、CBLOCK、表格的权威来源。
- 与 KLayout 的差异必须写进「已知差异」清单，避免被当成 bug 反复讨论。
