## 1. core（内核层，无 Qt）

### 1.1 几何

| 类 | 内容 | 说明 |
|---|---|---|
| `Dbu` | `int32_t` 强类型别名（`struct Dbu{int32_t v;}` 或 `using Dbu=int32_t`） | 数据库单位；建议用强类型防止与 µm 混用 |
| `Point` | `{Dbu x, y}`（也提供 `Point64` 用于变换中间结果） | 存储紧凑（8 B） |
| `Box` | `{Point min, max}`，含 `isEmpty/merge/contains/intersects/area` | 包围盒是所有空间操作的基础 |
| `Transform` | `{double a,b,c,d,tx,ty; bool mirror; double mag; double angleDeg;}` | GDS/OASIS 摆放的规范化表示（见 04） |
| `Polygon` | `std::span<const Point>` 或 `SmallVector<Point>` | 只读视图优先，减少拷贝 |
| `PathShape` | 中心线折线 + 宽度 + 端点类型(flush/round/halfWidth/slanted) | 渲染时按线宽展开 |
| `Repetition` | 类型 + 参数（1D/2D/3D，固定/可变步距） | 展开成实例位置序列的生成器 |

**约定**：几何类的坐标永远是 DBU 整数；只有 `Camera2D`、`Transform` 和渲染顶点做浮点转换。
**约定**：所有几何算法（相交、包含）在整数域计算，避免浮点误差导致「选中/未选中」抖动。

### 1.2 数据模型（可变）

```
Layout                               （唯一可写数据源；写入只经 Transaction）
 ├── name, units(Units), filePath, format, stats
 ├── layers: vector<LayerInfo>       （layer/datatype/name/properties；编辑可增删改）
 └── cells: vector<Cell>             （cellId 稳定；删除后空洞保留）
      Cell
       ├── name, cellId, bboxLocal, revision
       ├── parents: vector<CellId>   （反向引用，由 Layout 维护）
       ├── shapes:    SlotMap<Shape>     （图形：Boundary/Box/Path/Text/Node/XElement）
       └── instances: SlotMap<Instance>  （层次引用：Sref/Aref/Repetition）
```

| 类型 | 字段要点 |
|---|---|
| `Shape`（tagged 变体） | `kind; LayerKey layer; Box bbox;` + 具体字段（点序列/宽度/文本/原始字节） |
| `Instance` | `targetCellId` + `Transform` + 可选 `Repetition`（AREF/1D/2D） |
| `Cell::parents` | 反向引用，用于 bbox 上溯、实例树、删除保护 |
| `ElementKey` | `index(32b) \| generation(32b)`，删除后旧句柄自动失效 |
| `ElementRef` | `{CellId, ElementKey, isInstance}`，跨模块唯一的元素引用方式 |

**存储策略**

- 图形放在**按层分组**的 `SlotMap` 中（层内连续），渲染构建时天然得到 `LayerBatch`；
  单图元目标 ≤ 64 B，> 300 点的多边形旁路堆存储。
- 实例单独一个 `SlotMap`（数量通常远少于图形，且渲染/拾取路径不同）。
- 每个 cell 维护 `revision`：编辑后 +1，是「增量重建」和「乐观并发校验」的依据。

**为什么是可变的**：产品路线是「先查看、后编辑」，如果 V1 用不可变模型，V2 会把
渲染、选择、缓存、面板全部推翻。代价是 V1 就要写 `Transaction` 与 `SlotMap`（约 2 人周），
换来后续零重构。设计细节见 [09-编辑架构与事务模型](09-编辑架构与事务模型.md)。

### 1.3 单位与层

- `Units{ double dbuPerUserUnit; double metersPerDbu; }`，提供
  `micronsPerDbu()`、`toMicrons(Dbu)`、`fromMicrons(double)`；文件缺少 UNITS 时用默认（1 nm）。
- `LayerKey`：GDS 为 `(layer:uint16, datatype:uint16)`；OASIS 为 `(layer,datatype)` 或
  `(name)`（OASIS 允许用命名字符串表示层）。内部统一为
  `struct LayerKey { uint16_t layer; uint16_t datatype; uint32_t nameId; }`，`nameId=0` 表示无名。
- 层的**渲染顺序**由 `LayerStyleTable` 决定（默认按 `(layer,datatype)` 升序），而不是模型顺序。

### 1.4 错误与结果

`Result<T>` / `Error` / `ErrorCode`（见 01 第 5 节）。core 还提供
`WarningSink`（回调 + 计数），解析器把可恢复问题（未知记录、越界坐标被截断）推给它。

## 2. io（格式层）

### 2.1 职责边界

- **做**：字节 → `Layout`；`Layout` → 字节；格式嗅探；单位解析；错误定位；进度/取消；统计
  （cell 数、图元数、层级深度）；layer map 映射。
- **不做**：层次展开（属 scene）、LOD、渲染、UI 提示、图层配色决定权（样式归 render）。

### 2.2 组成

| 类 | 职责 |
|---|---|
| `FormatRegistry` | 后缀 + magic 双重识别，返回 `unique_ptr<FormatReader>` / `FormatWriter`；支持注册新格式 |
| `FormatReader` | 抽象：`open(path)`, `read(Layout&, IOOptions, Progress&) -> Result<ReadStats>` |
| `FormatWriter` | 抽象：`write(const Layout&, path, WriteOptions, Progress&) -> Result<WriteStats>` |
| `StreamReader` | 字节缓冲增强：`u8/u16/u32/i16/i32/f64/bytes/string(n)`，带偏移记录、越界检测（可复用 mmap） |
| `StreamWriter` | 对称的写入缓冲：定长/变长/real64 编码、延迟 flush、CBLOCK 分块 |
| `GdsReader` | GDSII 记录状态机（见 04 第 2 节） |
| `OasisReader` | OASIS 解析：varint、modal 变量、表格、CBLOCK、REPETITION |
| `GdsWriter` | 拓扑序写出、8191 点切分、`NODE`/未知记录原样回写（见 09 §7.2） |
| `OasisWriter` | 绝对坐标写出 + 可选 delta/表格/CBLOCK；offset table 加速重开（见 09 §7.3） |
| `FileIndex`（可选，D8） | cell 名 → 文件偏移，支持按需解析单个 cell |
| `UnitDecoder` | GDS 8 字节 real（16 进制指数）与 OASIS IEEE double 的解码/编码与单测 |
| `LayerMap` | `.lyp`（KLayout XML，**权威**）/ CSV / layermap 的读写：layer/datatype ↔ 名字/颜色/填充/顺序；读入保留未知 XML 元素，写出原样带回 |
| `GdsDumper` | 稳定文本化（`eda_dump` 用），用于解析与写出的 round-trip 对比 |

### 2.3 解析策略（先简单、后增强，接口不变）

| 阶段 | 策略 | 适用 |
|---|---|---|
| MVP | 单线程顺序读全文件，边读边建 `Layout`，每 64 KB 报一次进度 | < 200 MB |
| V1 | `mmap` + 批量解析 + 预估容量（先扫一遍 cell 数） | 200 MB ~ 2 GB |
| V2 | 两遍扫描建立 `FileIndex`，顶层 cell 相关结构优先解析，其余按需懒加载；超限走磁盘缓存 | > 2 GB |

**进度模型**：`Progress{ totalBytes, doneBytes, phase, cancellable }`；
OASIS 因压缩块无法精确预估，用「已读字节 / 文件大小」估算并在 UI 上标 `~`。

### 2.4 容错规范

| 情况 | 行为 |
|---|---|
| 未知记录类型 | 跳过（已知长度），warning |
| 记录长度非法（<4 或越界） | 终止解析，`CorruptRecord` + 偏移 |
| XY 点数与图元类型不匹配 | 丢弃该图元，warning |
| 引用了不存在的 cell | 保留引用，场景构建时画红色虚线框并 warning |
| 循环引用（A 引用 B 引用 A） | 场景构建时检测，截断并标红 |
| 坐标超出 int32 | 截断到 `int32` 范围，warning（GDS 本身不允许） |
| 文件被截断 | 返回已解析部分 + `TruncatedFile`，UI 提示部分加载 |

## 3. scene（场景/层次层）

### 3.1 核心思想

**不预先把 AREF 全量拍平**，而是构造一棵「显示用层次树」：
每个节点知道自己的变换、世界包围盒、层集合；渲染时按节点在屏幕上的尺寸决定
「画自己」「画包围盒」还是「继续递归」。这样既保留层次语义（选择、属性、定位都要它），
又能把绘制量控制在可控范围（见 05 第 4 节）。

```
SceneGraph（对应一次发布，不可变；编辑后只换脏条目）
 ├── topCell : CellId
 ├── cells   : CellId -> shared_ptr<const CellGeometry>   （浅拷贝复用未变 cell）
 │     CellGeometry { localBox; revision;
 │                    layers:    vector<LayerBatch>     // 本 cell 的形状
 │                    instances: vector<InstanceRef> }  // 子 cell 引用 + 变换
 ├── rootBox : 世界包围盒（渲染/相机用，由 topCell 递归算出）
 ├── index   : 可选的全局/分层空间索引（用于框选、吸附与全局搜索）
 └── generation : 发布序号（调试/缓存在此失效）
```

**没有全局 `SceneNode` 数组**：层次结构由「cell → instances → target cell」表达，
渲染时从 `topCell` 递归（05 §3）。这样编辑一个 cell 只需替换这一条 `CellGeometry`，
其余条目按 `shared_ptr` 复用，发布新快照的成本是 O(脏 cell 数)。

### 3.2 组成

| 类 | 职责 | 关键点 |
|---|---|---|
| `SceneBuilder` | 首次遍历 cell 层次，生成从 `topCell` 出发的 `CellGeometry` 集合 | 线程池执行，可取消；有实例数/深度上限 |
| `SceneUpdater` | 编辑后增量更新：重建脏 cell、上溯 bbox、发布新快照 | 见 09 §5.1；O(脏 cell 数) |
| `CellGeometry` | 单个 cell 的**本地坐标**几何（形状批次 + 实例列表） | 归一化：只存一次，供所有实例共享（D6 前提） |
| `LayerBatch` | 顶点数组 + 索引 + 包围盒 + 图元句柄映射 | 渲染层直接消费；上传 GPU 的最小单位 |
| `LodPolicy` | 纯函数策略：给定节点屏幕尺寸/图元数，返回绘制模式 | 可配置阈值，便于按机器调优 |
| `SpatialIndex` | 网格（MVP）或 R-Tree（V1） | 拾取、框选、吸附、区域统计 |
| `HitTester` | 点/矩形 → 命中集合（含实例路径） | 递归 + 包围盒剪枝 + 层过滤 |
| `SelectionSet` | 当前选择（`ElementRef` 集合） | 元素被删除时自动剔除（`selectionPruned`） |
| `SceneStats` | 图元数、节点数、内存估算、层统计 | 状态栏与诊断面板；编辑后增量刷新 |

### 3.3 层次展开规则（必须明确，否则各工具表现不一致）

1. 顶层单元由用户指定（默认第一个 `STRNAME` / `CELLNAME`）；切换顶层 = 重建 SceneGraph（快）。
2. 深度上限默认 64（可配置）；超过则停止递归并记 warning。
3. 实例节点总数上限默认 5×10⁶；超限则把更深的层折叠为「粗粒度实例」。
4. 循环引用：用「当前路径上的 cellId 栈」检测（不是全局 visited），因为同一 cell 可以合法地被
   多个父节点引用；检测到环就截断该分支并标红。
5. 空 cell（无图元、无引用）：保留节点，尺寸为 0，渲染时忽略但不报错。
6. 引用不存在的 cell：生成 `MissingCellNode`，渲染为品红色虚线框 + 单元名（便于定位坏数据）。
7. 变换合成：`childWorld = parentWorld * localTransform`（矩阵约定见 04）。

### 3.4 与渲染层的契约

- `SceneGraph` 只提供**只读迭代**：`visit(worldBox, lod, visitor)`（从 `topCell` 递归）。
  渲染层不遍历 `Layout`，只遍历 `SceneGraph`。
- 渲染层要求 `CellGeometry` 提供**分层的连续顶点块**（层内聚），以便一次 draw 覆盖一层。
- 场景层负责 `worldBox` 与 `layerMask` 的维护，渲染层不做几何计算。

### 3.5 重建 vs 增量

| 触发 | 操作 | 成本 |
|---|---|---|
| 打开文件 / 切换顶层单元 | 全量重建（异步：先发布粗 LOD 快照，再发布精 LOD 快照） | 秒级 |
| **编辑提交（形状）** | 只重建脏 cell 的 `CellGeometry` + 上溯 bbox + 发布新快照 | 毫秒 |
| **编辑提交（实例/层次）** | 重建父 cell 的 `CellGeometry` + 更新 parents + 上溯 bbox | 毫秒~几十毫秒 |
| **撤销/重做** | 与编辑提交同一路径（脏 cell 由事务逆操作产生） | 同上 |
| 图层显隐变化 | **不重建**：仅更新 `LayerVisibility`，渲染层按层跳过 | O(1) |
| 图层颜色/线宽 | 不重建：只改 `LayerStyleTable`，必要时重建 batch（GL 侧） | 毫秒 |
| 相机移动 | 不重建：纯渲染 | 每帧 |
| 选择变化 | 不重建：只更新高亮集合（overlay / ID buffer） | 毫秒 |

## 4. render（渲染层）

### 4.1 组成

| 类 | 职责 |
|---|---|
| `Camera2D` | 世界(µm) ↔ 屏幕(px) 变换、缩放/平移/适配、网格步长选择、DPR |
| `IRenderer` | 抽象后端：`initialize/resize/sync/render/pick/exportImage/shutdown` |
| `GlRenderer` | OpenGL 4.1：VAO/VBO、shader、逐层 draw call、实例化、ID buffer 拾取 |
| `SwRenderer` | QPainter 软件实现（验证 + 导出 PNG/SVG 的基础） |
| `LayerStyleTable` | `LayerKey → {color, fill, lineWidth, visible, zOrder, pattern}` |
| `FrameComposer` | 一帧绘制顺序：背景 → 版图 → 选择高亮 → 网格/标尺 → 测量/叠加 → 光标 |
| `OverlayPainter` | 用 QPainter 在 GL 之上绘制文本、标尺、测量、提示（不为文字写 GL 字形） |
| `EditOverlay` | 编辑预览（ghost）：待创建的图形、拖动中的副本、吸附点、尺寸提示（只读 `Layout`，不产生事务） |
| `Picker` | 拾取策略：CPU 命中（`HitTester`）或 GPU ID buffer |
| `ImageExporter` | 指定区域 + 分辨率 → QImage / SVG；复用离屏渲染 |
| `FrameStats` | 计时与计数，供状态栏与诊断 |

### 4.2 绘制顺序

1. 背景（深色/浅色主题）。
2. 版图（按 `zOrder` 升序；同层内：多边形 → 路径 → 文本）。
3. 选择高亮（描边 + 半透明填充），在**所有层之上**，避免被覆盖。
4. 网格 / 坐标轴 / 标尺（半透明，可关闭）。
5. 测量与书签标记。
6. **编辑预览层**（ghost 几何、吸附点、尺寸提示）。
7. 十字光标与坐标提示（仅鼠标悬停时）。

### 4.3 拾取策略

| 阶段 | 方案 | 说明 |
|---|---|---|
| MVP | CPU：相机反变换到世界坐标 → `HitTester::hitTest(point, tolerancePx)` | 简单准确；只对可见/命中盒剪枝；悬停 50 ms 节流 |
| V1 | GPU：离屏渲染 `elementId` 颜色图，读 1×1 像素 | O(1)，适合海量图元；需保证 ID 可逆映射 |
| V1+ | 混合：悬停用 GPU，框选用 CPU 空间索引 | 各自最优 |

> 无论哪种方案，最终返回的都是**稳定 ID**（`ElementRef`），UI 与插件只认它。

### 4.4 文本渲染

- 视口内文本上限默认 2000 条；按屏幕像素高度过滤（< 6 px 不画）。
- 用 `QPainter` 在 GL 之后绘制，字号固定为屏幕像素，避免缩放后发糊。
- 超长文本截断并提示；支持「只显示选中文本」模式。

## 5. ui（表现层）

### 5.1 主窗口布局

```
┌──────────────────────────── 菜单栏 / 工具栏 ────────────────────────────┐
│ 左侧 Dock        │              视口 (LayoutView)            │ 右侧 Dock │
│ - Cell 树        │  GL 渲染 + 叠加层 + 橡皮筋/编辑预览        │ - 图层    │
│ - 实例树         │  角标: "Editing: TOP"（编辑模式）          │ - 属性    │
│ - 书签/历史      │                                          │ - 编辑历史│
├──────────────────┴──────────────────────────────────────────┴───────────┤
│ 状态栏：坐标(µm/dbu) | 缩放 | 顶层单元 | 可视图元 | 内存 | FPS | 网格     │
└─────────────────────────────────────────────────────────────────────────┘
```

**界面语言：英文**（不做 i18n）。文案直接用英文常量；`tr()` 保留但不提供翻译文件。

### 5.2 面板

| 面板 | Qt 基类 | 数据模型 | 交互 |
|---|---|---|---|
| 单元树 `CellTreePanel` | `QTreeView` | `CellTreeModel`：层次 + 引用次数 + 包围盒 | 双击 → 设顶层/缩放；右键 → 仅显示该单元、复制名称、删除（V2） |
| 实例树 `InstanceTreePanel`（V1.5） | `QTreeView` | `InstanceTreeModel`：parents 反向索引 | 定位到引用处 |
| 图层 `LayerPanel` | `QTableView` | `LayerTableModel`：层号/数据类型/名称/颜色/可见/填充/图元数 | 勾选、双击改色、拖动改顺序、单选高亮该层 |
| 属性 `PropertyPanel` | 表单/`QTreeWidget` | 由 `SelectionSet` + `Layout` 现场生成 | V1 只读；**V2 可编辑**（坐标/宽度/文本/层号），修改走事务 |
| 编辑历史 `EditHistoryPanel`（V2） | `QListView` | `EditHistoryModel` | 单击选中、双击跳到该步；与撤销/重做按钮同步 |
| 测量 `MeasurePanel` | `QTableWidget` | `MeasureModel` | 增删/清除、显示 dX/dY/距离/角度/面积 |
| 消息 `MessagePanel` | `QTableView` | `WarningListModel` | 双击跳转到出错位置（可定位时） |
| 诊断（可选） | 对话框 | `FrameStats` | 仅开发者模式 |

### 5.3 视口与工具

- `LayoutView : QOpenGLWidget`：持有 `Document*`、`Camera2D`、`IRenderer*`、当前 `IViewportTool*`。
- 输入统一走工具状态机：`IViewportTool { mousePress/Move/Release/wheel/key; cursor(); }`。
- 浏览工具（V1）：`PanTool`、`ZoomTool`、`SelectTool`、`MeasureTool`、`RulerTool`。
- 编辑工具（V2）：`CreateBoxTool`、`CreatePolygonTool`、`CreatePathTool`、`CreateTextTool`、
  `MoveTool`（含拖动预览）、`VertexEditTool`、`InstanceTool`（放置/阵列）、`SnapEngine` 共用。
- 工具**只产生命令**（松手/双击结束时一条），由 `CommandBus` 开事务执行；
  渲染只用 `EditOverlay` 画预览（见 09 §5.3、11 §5.4）。
- 所有修改型操作（切换顶层、改图层、测量、编辑）都通过 `CommandRouter` 发命令，
  统一校验、统一发信号、统一可撤销；UI 不出现第二条写路径。

### 5.4 UI 刷新纪律

- 面板不轮询，只响应信号；模型内部用 `beginResetModel/endResetModel` 或细粒度 `dataChanged`。
- 相机变化 → `LayoutView::requestRepaint()`（合并到下一帧，≤ 60 Hz）；
  状态栏坐标更新单独节流到 30 Hz。
- 大数据量模型（图层表、单元树）**懒加载**：AREF 实例不展开，按需请求子项。

## 6. app（应用/控制器层）

| 类 | 职责 | 关键接口（草案） |
|---|---|---|
| `Application` | 启动、单实例、设置、主题、最近文件、崩溃处理 | `int run(argc, argv)` |
| `Document` | 一个打开的文件：Layout（可变）+ 快照 + 历史 + 样式 + 选择 + 相机 + 统计 | `layout()`, `snapshot()`, `history()`, `styles()`, `selection()`, `isDirty()`, `lockEditing()` |
| `DocumentController` | 文档级编排（打开/关闭/保存/视图/图层/导出）；**命令目标方法对外私有**，只由 `CommandRouter` 调用 | `openFile/closeDocument/save/saveAs`（内部实现），对外仅信号与只读查询 |
| `CommandRouter` | Qt 适配器：QAction/控制台/脚本/socket → `command::CommandBus`；统一 enabled 判定 | `invoke(id, args)`, `invokeText(line)`, `isEnabled(id)` |
| `EditController` | **命令内部编排器**：把操作请求变成事务并提交，然后触发增量更新；不再是 UI 入口 | `apply(OperationRequest)/undo/redo`（`private`，friend `CommandBus` 实现） |
| `TaskRunner` | 线程池 + 任务句柄（进度、取消、结果） | `run(name, fn, onProgress, onDone)` |
| `EditHistory` | 撤销/重做栈（事务、保存点、内存上限） | `push/undo/redo/canUndo/isAtSavePoint/setMemoryLimit` |
| `Settings` | 强类型设置访问（默认值集中一处） | `renderOptions()`, `layerDefaults()`, `editOptions()` |
| `RecentFiles` | 最近文件列表（QSettings） | `add/remove/list` |
| `Logging` | `QLoggingCategory` 初始化、文件日志轮转 | `init(argv)` |

**DocumentController 的编排职责**

1. 开文件：选格式 → 建任务 → 进度对话框 → 成功后建 Document → 设顶层 → 触发首帧 → 加最近文件。
2. 关闭：dirty → 询问保存 → 取消未完成任务 → 保存侧车 → 释放。
3. 保存：`lockEditing()` → 选出 writer → 后台写临时文件 → 校验 → 原子替换 → `markSaved()`。
4. 任何命令先校验状态（无文档时忽略缩放命令），失败时给可读提示。
5. 对外只发信号（`documentOpened/documentClosed/layersChanged/selectionChanged/cameraChanged/`
   `sceneChanged/editCommitted/dirtyChanged`），面板订阅信号，模块间不直接引用。

**命令示例（设计意图，不是实现）**

> 下表每一项在 11 §7 都有一个稳定的命令 ID（如 `view.topCell.set/1`）；
> 新增功能时先加命令 ID，再接菜单/快捷键/面板。

| 命令 | 参数 | 副作用 | 可撤销 |
|---|---|---|---|
| `OpenFile` | path | 新 Document | 否 |
| `SetTopCell` | cellId | 重建场景 + 适配视图 | 是（记录旧顶层+相机） |
| `SetLayerVisible` | layerKey, bool | 样式表更新 + 重绘 + `lypDirty` | 否（视图状态，与 KLayout 一致） |
| `SetLayerColor` | layerKey, color | 样式表更新 + 重建 batch + `lypDirty` | 否 |
| `AddMeasure` | 两点/三点 | 叠加层 + 面板 | 是 |
| `ExportImage` | 区域/路径/DPI | 生成文件 | 否 |
| `MoveSelection` | refs, delta | 事务 → 增量重建 → 重绘 | 是 |
| `CreateShape` | shape, layer | 事务 → 增量重建 → 选择新元素 | 是 |
| `DeleteSelection` | refs | 事务 → 增量重建 → 清选择 | 是 |
| `SetInstanceTarget` | ref, cellId | 事务（环路检查）→ 两侧 parents 更新 | 是 |

### 6.1 命令层与控制器（11）

```
ui（QAction / 工具 / 面板 / 控制台）
   │  invoke(id, args)
   ▼
app::CommandRouter ──► command::CommandBus ──► editing::EditOps ──► core::Transaction ──► Layout
   ▲                        │
   │                        ├── core::EditHistory（undo/redo）
plugin / CLI / socket ─────┘└── ICommandHost（app 实现：场景重建、选择、TaskRunner）
```

- `ui` 只认识**命令 ID 与参数值类型**；拿不到 `Document*`/`Layout&` 的写权限。
- `CommandRouter` 负责 Qt 侧：动作表、enabled 状态、错误提示、控制台/脚本/socket 接入。
- `DocumentController`/`EditController` 的方法改为 `private`，只对 `CommandRouter`/`CommandBus`
  开放（编译期隔离，和 `Layout` 只对 `Transaction` 开放同理）。
- `File` 类命令异步：进入时 `lockEditing()`，结果回投后由 `CommandRouter::executed` 通知 UI。

## 7. editing（编辑层，V2 起；接口 V1 就定型）

### 7.1 职责边界

- **做**：把「用户意图」变成对 `Layout` 的**事务性修改**；撤销/重做；吸附；层次合法性检查；
  布尔运算（merge/and/or/xor/size，V2 E3）；编辑检查（自交/零宽/重复/越界，V2 E3）。
- **不做**：鼠标事件（ui）、渲染（render）、文件读写（io）、场景重建（scene）。
- **为什么单独成层**：编辑的难点是语义与不变量（句柄失效、环路、bbox 上溯、撤销精确还原），
  这些都能在没有 GUI 的情况下测试。

### 7.2 组成

| 类 | 职责 | 关键点 |
|---|---|---|
| `EditSession` | 一次编辑会话：当前编辑目标 cell、选择集、吸附设置、活动事务 | 保证同一时刻只有一个事务 |
| `Transaction` | 记录前像/后像并提交（见 09 §3.1） | 嵌套事务合并为一步撤销 |
| `EditHistory` | 撤销/重做栈 + 保存点 + 内存上限 | 撤销回到保存点自动清 dirty |
| `EditOps` | 具体操作：创建/移动/复制/删除/旋转/镜像/顶点编辑/实例操作 | 全部包成"请求 → 事务 → 变更集" |
| `SnapEngine` | 顶点/边/中点/实例原点/网格的吸附与角度约束 | 与拾取共用空间索引 |
| `HierarchyOps` | 建/删/改名 cell、放置实例、改目标 cell、打散、Make Cell | 环路检查 + parents 维护 |
| `EditCheck`（V2 E3） | 自交、零宽、重复、越界、非网格对齐 | 输出问题列表，可定位 |
| `BooleanOps`（V2 E3） | merge/and/or/xor/size，封装 Clipper2 | 输入输出均为 DBU 整数；大结果分块提交 |

### 7.3 与其他模块的契约

- 输入：`editing::OperationRequest`（`CreateRequest / MoveRequest / DeleteRequest / TransformRequest /`
  `InstanceRequest / LayerChangeRequest / BatchRequest ...`）+ 当前 `Layout` 的只读视图 + `SelectionSet`。
- 输出：`Result<CommittedEdit>`，其中 `CommittedEdit { std::vector<CellId> dirtyCells; label; }`。
- **唯一调用者**是 `command::CommandBus` 的 `Edit` 分支（11 §4.2）；UI 不直接调 `EditOps`。
- `app::CommandRouter` 拿到 `CommittedEdit` 后：发布快照 → 发 `executed` 信号 → 刷新面板。
- **失败不留痕**：任何校验失败都回滚到事务开始前（内存与句柄状态完全一致）。

## 8. plugin（可选，V2）

- `IViewerPlugin`：`name/version/initialize(IViewerHost*)`；`IViewerHost` 暴露
  `Document` 只读访问 + 注册菜单/工具栏/叠加层/面板的 API；V2 的写入能力改为
  `commands()->execute(一行命令文本)`（`ICommandSink`，见 11 §8）——插件不拿 `Layout&`，
  写入只能在命令层开启的事务内发生，因此撤销/校验/日志与 UI 完全一致。
- `QPluginLoader` 从 `<app>/plugins` 加载，元数据用 `Q_PLUGIN_METADATA`。
- 插件与主程序之间只传**纯 C++ 抽象接口 + 版本号**，不跨共享库边界传 STL 容器
  （macOS clang 与 Linux gcc 的 `libstdc++`/`libc++` ABI 不同）；需要传字符串用
  `const char*` + 长度或 `QString`。插件只保证同编译器同 Qt 版本内兼容。
